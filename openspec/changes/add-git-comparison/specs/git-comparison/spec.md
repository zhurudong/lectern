## Purpose

定义 Lectern 如何在用户已授权的本地项目中发现 Git 数据、选择两个本地端点并呈现可信的只读差异，使用户无需 checkout、联网或修改仓库即可审查分支、Tag、提交及当前工作区的变化。

## ADDED Requirements

### Requirement: Git 对比的可用性必须可解释

Git 对比 SHALL 只在项目目录模式中工作，并且只读取用户已授权项目根目录内可达的 Git 元数据。界面 SHALL 提供“文件 / 变更”两个视图入口；无法读取 Git 数据时，“变更”视图 SHALL 说明具体原因，MUST NOT 把“无法比较”显示成“没有变更”。

#### Scenario: 标准本地仓库可进入变更视图

- **WHEN** 用户打开的项目根目录包含可读的 `.git` 目录，并进入“变更”视图
- **THEN** 查看器加载本地引用并显示 Git 对比工作区

#### Scenario: 非 Git 目录

- **WHEN** 用户打开的目录不包含可达的 Git 元数据
- **THEN** “变更”视图明确提示该目录不是可读取的 Git 仓库，并保留返回文件阅读视图的入口

#### Scenario: Gitdir 位于授权范围之外

- **WHEN** 项目根的 `.git` 是文件，且其 `gitdir` 指向用户已授权目录之外（例如 linked worktree 或部分 submodule 布局）
- **THEN** “变更”视图说明浏览器无权读取外部对象库，MUST NOT 报成仓库损坏，也 MUST NOT 请求更广泛的隐式权限

#### Scenario: 单文件模式没有 Git 对比

- **WHEN** 用户通过“打开文件”进入单文件模式
- **THEN** 查看器不伪造仓库上下文，并明确说明 Git 对比需要打开项目目录

### Requirement: 项目视图切换必须保持侧栏几何与临时对比会话

同一项目内的“文件”和“变更”视图 SHALL 共享同一侧栏宽度、拖拽范围和持久化值，“变更”视图的文件列表侧栏 SHALL 可以拖拽调整宽度。用户第一次打开“变更”后，在同一项目内切换到“文件”再切回“变更”时，查看器 MUST 保留对比端点、比较模式、选中的变更文件、已加载的对比结果以及 diff 阅读位置，MUST NOT 因视图切换重新探测仓库、重新计算对比或闪回初始加载态。用户显式触发“重新比较”时，查看器 SHALL 使用现有端点和比较模式重新建立结果；切换项目根目录或离开项目模式时，查看器 SHALL 清除原项目的临时对比会话。

#### Scenario: 文件与变更共享可调整侧栏宽度

- **WHEN** 用户在“文件”视图拖动左侧分隔线后切换到“变更”，或在“变更”视图拖动同一分隔线后切回“文件”
- **THEN** 两个视图使用相同的侧栏宽度、最小值、最大值和持久化值，页面不因切换而跳回固定宽度

#### Scenario: 临时切换视图精确恢复对比现场

- **WHEN** 用户已完成一次 Git 对比、选择某个变更文件并滚动 diff，然后切到“文件”再切回“变更”
- **THEN** 原端点、比较模式、变更清单、选中文件、已加载内容和 diff 阅读位置立即恢复，且不会重新探测仓库或重新计算对比

#### Scenario: 用户显式重新比较当前本地状态

- **WHEN** 用户在“变更”视图触发“重新比较”
- **THEN** 查看器保留当前端点和比较模式，重新读取本地仓库与工作区并重建比较结果

#### Scenario: 项目边界清除旧会话

- **WHEN** 用户切换到不同项目根目录或离开项目模式
- **THEN** 原项目的 Git worker、缓存和临时对比会话被释放，新项目不会继承旧项目的端点、文件或阅读位置

### Requirement: 顶部双选择器必须覆盖五类本地来源

Git 对比工作区 SHALL 在顶部持续显示 `基准 [引用] ⇄ 目标 [引用] [比较模式]`。点击任一引用 SHALL 在该控件下方打开锚定式来源面板，而非居中弹窗或侧栏抽屉。来源面板 SHALL 按“当前工作区、本地分支、远程跟踪分支、Tag、Commit SHA”组织，并显示已解析提交的短 SHA；当前工作区仅作为目标端点提供。

#### Scenario: 选择本地分支

- **WHEN** 用户打开基准或目标选择器并选择一个本地分支
- **THEN** 对应端点更新为该分支当前在本地解析到的提交，选择器同时显示分支名与短 SHA

#### Scenario: 远程跟踪分支是本地快照

- **WHEN** 来源面板列出或选中 `origin/main` 等远程跟踪分支
- **THEN** 该分支旁明确标注“本地快照”，且查看器只使用本地已有引用，MUST NOT fetch、探测远端或暗示它代表远端最新状态

#### Scenario: 选择 Tag

- **WHEN** 用户选择轻量 Tag 或 annotated Tag
- **THEN** 查看器将其解析到本地 commit 后作为端点，并显示 Tag 名与解析后的短 SHA

#### Scenario: 输入有效 Commit SHA

- **WHEN** 用户输入本地存在、能够唯一解析且最终指向 commit 的完整或缩写 SHA 并确认
- **THEN** 面板关闭，对应端点显示该 commit 的短 SHA，并重新计算对比

#### Scenario: Commit SHA 无效、歧义或不是 commit

- **WHEN** 输入无法解析、对应多个对象，或最终对象不是 commit
- **THEN** 来源面板在输入处说明原因，保留原端点与当前结果，MUST NOT 静默选择任意对象

#### Scenario: 搜索引用

- **WHEN** 用户在来源面板搜索框输入分支名、Tag 名或 SHA 片段
- **THEN** 面板在各来源组内过滤本地候选，并保留候选所属来源及“本地快照”标识

#### Scenario: 当前工作区不能成为基准

- **WHEN** 用户打开基准选择器
- **THEN** 当前工作区不可被选为基准，并有可发现的说明指出未提交状态只作为审查目标

#### Scenario: 交换两个不可变端点

- **WHEN** 基准和目标都是分支、远程跟踪分支、Tag 或 Commit，用户触发交换
- **THEN** 两个端点互换并按当前比较模式重新计算

#### Scenario: 目标是当前工作区时不可交换

- **WHEN** 目标是当前工作区，用户到达交换控件
- **THEN** 控件呈禁用状态并说明当前工作区不能成为基准

#### Scenario: 仅用键盘完成选择

- **WHEN** 键盘用户打开来源面板，使用搜索、方向键、Enter 或 Escape 操作
- **THEN** 用户可选择引用或取消；取消后焦点返回触发选择器，且端点不变

### Requirement: 审查改动与直接比较必须具有不同且明确的语义

查看器 SHALL 提供“审查改动”和“直接比较”两种模式，默认使用“审查改动”。“审查改动” SHALL 以基准 commit 与目标 commit 的 merge base 为左端快照，再与目标快照比较；“直接比较” SHALL 直接比较用户选中的两个端点快照。目标为当前工作区时，其 commit 图位置取当前 HEAD，目标快照取磁盘上的当前工作区内容。

#### Scenario: 默认进入审查改动

- **WHEN** Git 仓库首次进入变更视图
- **THEN** 目标默认为当前工作区，基准优先采用本地可识别的默认分支、否则采用当前 HEAD，并以“审查改动”计算结果

#### Scenario: 审查两个已分叉分支

- **WHEN** 基准和目标分支拥有共同祖先且用户选择“审查改动”
- **THEN** 结果只描述从 merge base 到目标端点引入的变化，不把基准分支独有提交反向显示为目标删除

#### Scenario: 直接比较两个端点

- **WHEN** 用户切换到“直接比较”
- **THEN** 结果描述基准端点快照到目标端点快照的直接变化，且引用选择保持不变

#### Scenario: 审查当前工作区

- **WHEN** 目标为当前工作区
- **THEN** 结果包含目标 HEAD 相对 merge base 的已提交变化，以及磁盘中相对 HEAD 的 tracked 修改、删除和未被仓库内 `.gitignore` 或 `.git/info/exclude` 忽略的 untracked 文件；`.git` 与这些 ignore 规则排除的文件不进入结果，授权范围之外的全局 ignore 规则不被读取

#### Scenario: 两个历史无共同祖先

- **WHEN** “审查改动”的两个 commit 不存在共同祖先
- **THEN** 查看器说明无法建立审查基线并提供切换到“直接比较”的入口，MUST NOT 自动改变语义或伪造 merge base

#### Scenario: 存在多个最佳共同祖先

- **WHEN** commit 图存在多个同等最佳 merge base，无法在不合并基准的情况下得到唯一审查起点
- **THEN** 查看器说明该历史形态暂不支持“审查改动”并提供“直接比较”，MUST NOT 任取一个共同祖先后把结果称为精确审查差异

### Requirement: 变更文件列表必须给出完整且稳定的总览

完成端点解析后，查看器 SHALL 按新增、修改、删除分组列出发生变化的路径，显示各组数量与总计，并使用稳定的路径排序。内容相同的路径 MUST NOT 出现在列表中；两个 Git commit 快照之间仅文件模式或 Git 对象类型发生变化的路径 SHALL 作为修改显示。当前工作区只改 POSIX 权限位而不改内容的情况 SHALL 明确列为浏览器能力边界，因为 File System Access API 不提供该信息。首次得到非空结果时 SHALL 选择第一项。

#### Scenario: 展示新增、修改和删除

- **WHEN** 对比结果同时包含新增、内容修改和删除的普通文件
- **THEN** 变更文件导航按三种状态分组，数量与实际路径一致，选择任一项会在文件差异视图显示对应差异

#### Scenario: 没有变化

- **WHEN** 两个有效端点的快照相同
- **THEN** 查看器明确显示“没有变化”，而不是空白列表或加载失败状态

#### Scenario: 文件类型或模式发生变化

- **WHEN** 两个 Git commit 快照中同一路径的 Git 对象类型、可执行位或 submodule commit 发生变化
- **THEN** 该路径显示为修改，并以元数据差异说明旧值与新值；非普通文本对象 MUST NOT 被当作文本解码

#### Scenario: 当前工作区只有权限位变化

- **WHEN** 目标为当前工作区且磁盘文件仅改变 POSIX 权限位、内容未变
- **THEN** 查看器的“未发现内容变化”状态同时说明浏览器无法检测工作区权限位变化，MUST NOT 无限定地宣称工作区与基准完全相同

#### Scenario: 连续快速切换引用

- **WHEN** 用户在上一次比较尚未完成时再次选择引用或模式
- **THEN** 界面标记最新请求正在计算，旧请求即使稍后完成也 MUST NOT 覆盖最新选择与结果

### Requirement: 文件差异必须是只读且可导航的统一视图

普通文本文件 SHALL 以统一差异视图展示，包含文件路径、旧/新行号、增删标记、语法可读的文本及当前差异段序号。查看器 SHALL 提供上一处/下一处差异的可点击与键盘通道。差异文本可选择和复制，但 MUST NOT 出现接受、拒绝、回退、合并、编辑或写回控件。

#### Scenario: 阅读普通文本差异

- **WHEN** 用户在变更列表中选择一个有多处变化的文本文件
- **THEN** 文件差异视图展示正确的统一差异、旧/新行号与差异段总数，默认定位第一处变化

#### Scenario: 在差异段之间导航

- **WHEN** 用户触发“上一处”或“下一处”差异的按钮或键盘操作
- **THEN** 视图定位到相邻差异段并更新当前位置计数，边界处不会越界或失去焦点

#### Scenario: 对比视图保持只读

- **WHEN** 用户点击差异装订线、按输入键、粘贴或寻找合并操作
- **THEN** 文档内容和磁盘内容均不变化，且界面中不存在接受、拒绝、回退或合并控件

#### Scenario: 返回文件视图

- **WHEN** 用户从“变更”切回“文件”
- **THEN** 文件阅读状态仍可继续，焦点落在可预测的可交互位置，不因临时对比态而进入空白或丢失项目上下文

### Requirement: 不完整或不精确的差异必须显式披露

查看器 MUST NOT 把部分、近似或无法读取的结果呈现为完整精确的 diff。二进制、任一侧超过 5 MB、对象缺失或损坏、算法预算耗尽等情况 SHALL 在文件级显示原因和仍然可信的元数据；错误 MUST 隔离到受影响文件或当前比较，不得使整个应用白屏。

#### Scenario: 二进制文件发生变化

- **WHEN** 任一侧内容被识别为二进制
- **THEN** 查看器显示“二进制文件发生变化”及可用的旧/新大小或对象信息，MUST NOT 输出乱码或伪造文本 diff

#### Scenario: 文件超过文本对比上限

- **WHEN** 任一侧普通文件内容超过 5 MB
- **THEN** 查看器不计算或展示部分文本 diff，并明确显示旧/新大小以及“未生成完整文本差异”

#### Scenario: 差异算法给出近似结果

- **WHEN** 文本差异因时间或复杂度预算而无法得到精确结果
- **THEN** 视图在结果旁持续标注“近似结果，可能遗漏细节”，MUST NOT 仅以看似完整的单一大块变化替代披露

#### Scenario: 本地 Git 对象缺失或损坏

- **WHEN** 解析引用、commit、tree、blob、pack 或 delta 时遇到缺失或损坏对象
- **THEN** 查看器指出无法完成的端点或文件及本地原因，保留可恢复操作入口，MUST NOT 尝试联网补对象

### Requirement: Git 对比必须维持零网络、只读和空权限不变量

Git 对比 SHALL 只读取已授权目录中的工作区文件和 `.git` 数据。实现 MUST NOT 发起网络请求，MUST NOT 修改工作区、`.git`、index、refs、对象、锁文件或配置，也 MUST NOT 增加扩展权限、主机权限、内容脚本或 CSP 覆写。远程跟踪分支和 Git LFS pointer 只按本地内容展示。

#### Scenario: 离线使用全部本地来源

- **WHEN** 设备离线且本地仓库拥有所选分支、远程跟踪分支、Tag 或 commit 对象
- **THEN** 引用选择与差异展示正常工作，结果不依赖任何远程服务

#### Scenario: 发布产物继续通过不变量检查

- **WHEN** 从当前源码构建发布产物并运行既有静态不变量检查
- **THEN** 网络 API、文件写入 API 与新增权限仍为零命中，包括 Git 依赖及其传递依赖生成的代码

#### Scenario: 对比前后仓库未被修改

- **WHEN** 用户完成任意引用选择、差异计算和文件阅读
- **THEN** 工作区与 `.git` 中所有文件内容和引用保持不变，查看器不创建 lock、缓存或临时文件

### Requirement: Git 对比界面必须延续现有主题与无障碍契约

变更列表、顶部选择器、来源面板、状态提示和差异视图 SHALL 在浅色与暗色主题下保持可读，并提供可识别的焦点状态、语义名称和键盘路径。颜色 MUST NOT 是区分新增、修改、删除或错误状态的唯一手段。

#### Scenario: 暗色主题下完成对比

- **WHEN** 用户在暗色主题进入变更视图、选择引用并阅读差异
- **THEN** 所有文本、边界、选中态、增删标记和焦点状态均清晰可辨，不出现只在浅色主题可见的信息

#### Scenario: 屏幕阅读器识别选择器与状态

- **WHEN** 辅助技术遍历引用选择器、比较模式、变更文件和差异导航
- **THEN** 每个控件具有可理解的名称、当前值和状态，远程跟踪分支的“本地快照”含义不只通过视觉徽标表达
