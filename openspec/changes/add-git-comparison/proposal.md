## Why

Lectern 目前只能阅读工作区的当前快照，无法回答代码审查最基本的问题：相对某个基准，哪些文件和代码发生了变化。Git 对比把“读代码”推进到“审改动”，并且可以利用已授权目录中的本地 Git 数据，在不联网、不写磁盘的前提下覆盖未推送提交和未提交改动。

## What Changes

- 新增 Git 对比工作区：以变更文件列表 + 统一差异视图呈现两个 Git 端点之间的改动。
- “文件 / 变更”共享同一份左侧栏宽度、拖拽范围与持久化设置；进入变更视图后，变更文件导航 MUST 可调整宽度，视图切换不得造成左侧栏跳变。
- 同一项目内临时切回“文件”时保留 Git 对比会话，包括端点、比较模式、选中变更文件、已加载结果与差异阅读位置；只有显式“重新比较”、更换项目或离开项目才重新建立结果。
- 分支选择交互采用已选定的第 2 稿：“顶部双选择器 + 锚定式来源面板”，即 `基准 [ref] ⇄ 目标 [ref] [审查改动/直接比较]`，引用面板不使用居中弹窗或侧栏抽屉。该选择只约束“如何选择对比分支”，不代表整体 Git 对比页面视觉已经选定。
- 整体 Git 对比页面的布局与视觉层级尚未选定；进入 UI 实现前必须先产出完整页面视觉方案并由用户明确选择，数据与 Git 读取层不依赖该选择。
- 引用选择器支持五类本地来源：当前工作区、本地分支、远程跟踪分支（明确标注“本地快照”）、Tag、Commit SHA；不得为补全引用而 fetch 或访问远程服务。
- 默认使用“审查改动”：以 merge base 作为基准展示目标分支引入的变化；同时提供“直接比较”，对两个端点快照做直接差异。
- 当前工作区作为目标侧来源，组合当前 HEAD 与未提交文件；分支、Tag 和 Commit 只解析本地 `.git` 中已经存在的引用与对象。
- 对非 Git 目录、对象缺失或损坏、SHA 无效或歧义、`.git` 指向授权目录之外（linked worktree/submodule）等情况提供可解释降级，不白屏、不伪造空差异。
- 延续产品不变量：只读、零网络、空扩展权限；不提供 fetch、checkout、stage、revert、merge、commit、编辑或写回能力。
- 本变更不加入 AI 代码解读。后续 AI 能力可消费本变更产出的结构化 diff 与定位信息，但必须独立定义模型、证据和隐私契约。

## Capabilities

### New Capabilities

- `git-comparison`: 定义本地 Git 仓库识别、引用选择与解析、审查/直接比较语义、变更文件和统一差异呈现，以及只读零网络和失败降级契约。

### Modified Capabilities

无。

## Impact

- 新增 Git 对象读取与引用解析层，必须覆盖 loose object、pack index、packfile 以及 OFS/REF delta；loose-only 在典型 clone 仓库中不可接受。
- 新增 Git 对比状态、引用选择面板、变更文件列表与统一 diff 渲染，并接入现有主题、焦点和键盘导航体系。
- 调整项目视图壳层与 Git worker 生命周期：两个视图复用侧栏尺寸状态，Git 对比首次打开后在当前项目内保持挂载，并提供显式重新比较入口。
- 新增聚焦只读场景、按 pack offset 随机读取的 Git 对象层；通用 Git 库若会整包读取 packfile，则不能用于真实仓库主路径。文本差异采用 `@codemirror/merge`；Git ignore 语义可采用经过审计的轻量依赖。发布包仍须通过既有零网络、只读、空权限静态检查。
- 自动化需增加真实 Git fixture，覆盖 loose/packed/OFS delta/REF delta、分支/远程跟踪分支/Tag/SHA、工作区改动、二进制/大文件和错误降级；授权边界外 `.git` 需真机核验。
