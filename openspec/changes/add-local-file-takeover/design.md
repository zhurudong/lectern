## Context

见 proposal.md 的动机。当前后台只响应扩展图标，预览与符号 Worker 都接收原生文件句柄，设置分散在 localStorage。工作区同时有 AI 终端未提交改动，必须保留其独立构建模式。

## Goals / Non-Goals

**Goals:** 自动接管在浏览器加载/下载本地文件前完成，复用单文件阅读路径，权限和读取边界可以验证。

**Non-Goals:** 不改变系统文件关联，不获得父目录或开启单文件跨文件搜索；不添加远程文件读取。

## Decisions

1. 使用 MV3 declarativeNetRequestWithHostAccess 动态规则，仅匹配 `file:///` 的 `main_frame`，以 regexSubstitution 将原始 URL 放进查看器片段。Chrome 152 临时扩展实测 txt/md/sql/java 同标签页重定向且没有触发下载。相比 webNavigation 监听后更新标签页，声明式规则在导航前生效，避免异步后台与下载竞态。查看器作为仅对 file 地址可访问的扩展资源；不暴露其他脚本。使用 isRegexSupported 预检，长后缀超出 RE2 的 2 KiB 编译限制时仅拆分等价分支，并限制检查次数及总规则数；不放宽路径边界。
2. `chrome.storage.local` 存配置，后台负责规范化配置与串行更新动态规则，页面通过后台消息等待真正保存完成。首次默认开启，格式表派生支持后缀，排除 HTML/图片的默认项；不增加独立的扩展名清单。设置使用原生 dialog 管理焦点与 Escape。
3. 自动入口将 URL 读取成真实 File 快照；文件消费者接收 File 或原生句柄，Worker 直接结构化克隆 File。拒绝伪造 getFile 方法的“句柄”，避免 Worker 克隆异常。浏览器刷新重新读取 URL；项目模式保持原有句柄和重读语义。
4. 唯一读取模块以原样公共 ES module 发布，协议验证、禁重定向、无缓存、本机主机限制以及 64 MiB 流式读取上限放在同一个审计边界。使用 manual 重定向模式；Chrome 对无尾斜杠目录给出的 basic/status-0 响应归还到原地址加斜杠的浏览器目录页，不接受响应提供的跳转目标。构建门禁对它验证固定摘要，其余脚本继续禁传输符号；CSP 限制连接为 self 与 file，AI 构建额外保留既有 loopback WebSocket。不能通过改名/隐藏 fetch 绕开门禁，也不继续声称“没有任何读取 API”。
5. 自动入口有加载、失败、重试和手动选择状态；用户主动离开后取消在途读取，防止迟到结果把新页面替换掉。URL 放片段避免它成为扩展资源的请求查询参数；Markdown 页内链接只滚动，不覆盖来源片段。读取结果不存入最近项目。

## Risks / Trade-offs

- Chrome 文件网址开关需用户手动开启 → 设置显示实际授权状态、进入扩展详情，原生选择器仍可用。
- 旧版本可能存在不同导航行为 → 真 Chrome E2E 验证关键格式、开关、特殊文件名、禁用配置和子资源隔离；最低支持版本行为需单独声明测试范围。
- File 快照不会后台监听外部变化 → 刷新重新读盘，沿用手动触发读取的产品模型。
- 自动读取整份文件的内存约束 → 64 MiB 明确上限，超过时引导选择器；已有大文本截断仍保留。
- 配置与动态规则是两个 API → 后台串行保存、失败回滚，读取状态时从已持久化配置重建规则。

## Migration Plan

新增权限后重新加载扩展，在设置开启文件网址访问。现有项目句柄、主题、布局存储键不变。关闭功能并保存会移除接管规则；回滚版本恢复原有选择器入口。
