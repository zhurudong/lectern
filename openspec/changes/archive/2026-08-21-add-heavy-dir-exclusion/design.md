## Context

目录树与文件名索引是**两条独立的遍历**(`treeStore.loadChildren` 在主线程按需展开,`indexWorker` 在 Worker 里全树 walk),符号索引再从索引结果派发。现状三处都是裸 `entries()`,无任何名单。行模型 `TreeRow` 已是联合类型(`'node' | 'loading'`),虚拟滚动按 `visibleRows()` 的扁平数组渲染。

## Goals / Non-Goals

**Goals:** 一份排除判定被三个消费者共用;排除可见可逆;"可浏览"与"被索引"分离且对用户可见。

**Non-Goals:** 不解析 `.gitignore`(理由见 D1);不做用户自定义名单(可作后续);不改既有刷新/展开语义。

## Decisions

### D1 按**目录名**匹配固定名单,不解析 `.gitignore`

- `.gitignore` 会排除掉用户**明确想读**的东西(构建产物有时正是要读的对象),而我们是阅读器不是构建工具;
- 解析它是个真工程(否定规则、嵌套 `.gitignore`、glob 语义),收益不匹配;
- 最关键:**用户能不能解释"为什么这个目录不见了"**。固定名单可以("因为它叫 `node_modules`"),`.gitignore` 规则链不行 —— 而我们刚把"排除必须可见"写进 spec,**一个看得见却解释不了的排除,只完成了一半**。

### D2 判定函数放 `src/lib/`,主线程与 Worker 共用同一模块

纯函数、无 DOM/FSA 依赖,可被 `treeStore`(主线程)、`indexWorker`(Worker)、符号索引派发同时 import。**这是"单一实现"的落点** —— 不是靠三处约定同一份名单,而是三处 import 同一个函数。

### D3 "已隐藏 N 项"复用既有行模型,不新建渲染通道

`TreeRow` 加一个 `'hidden'` 变体(带该层被隐藏的条目数与展开回调),`visibleRows()` 在该层末尾产出一行。虚拟滚动、行高、滚动定位全部照旧生效 —— **复用既有机制,不新建平行体系**(本项目已反复用这条)。

### D4 "可浏览但不被索引"几乎是**免费**的,因为树与索引本就是两条独立遍历

用户展开被排除目录 → 只影响 `treeStore` 这条遍历;索引那条遍历在 Worker 里独立按同一判定跳过,**不因树的展开状态而改变**。

**⚠️ 更正(2026-08-21,实现期由夹具抓出):上面这个推理只覆盖了"遍历",而索引有第三条写入路径。** `ensureFileSymbols`(预览文件时按需抽取 / 指纹不符时就地重抽)会把**任何被预览过的文件**写回项目索引 —— 它不是遍历,所以不在"两条独立遍历"这个模型里。后果:只要预览一次 `node_modules/lodash/index.js`,其中的符号就能被全局符号搜索搜到,**「可浏览但不被索引」从这条路整个漏掉**。已用同一个 `isInExcludedRelPath` 在写回处挡住(与批量写入处共用同一判定)。

**教训比这个 bug 本身重要**:我说"树与索引是两条独立遍历,所以排除是免费的" —— **"两条"是我枚举出来的,不是我验证出来的**。免费的前提不是"它们独立",而是"**所有写入索引的路径都被我数全了**"。**枚举型推理的风险在于它读起来像穷举,而它只是我当时想到的那些。** 下一个动索引的人若新增第四条写入路径(如后台预热、外部触发的重抽),这条排除同样会从那里漏掉 —— **所以判定必须挂在"写入索引"这个动作上,而不是挂在"遍历"这个入口上。**

**所以不需要在树与索引之间同步"展开态"** —— 两者天然解耦。这是个值得记下的性质:**当两个消费者本就各自遍历时,"对一方可见、对另一方不可见"不需要额外机制,只需要它们对同一判定有不同的应用时机。** 反过来说,如果将来有人把索引改成复用树的遍历结果(听起来更省),**这个免费性质就没了**,3.x 那组要求会变成需要显式同步的状态 —— 届时要重新评估。

## Risks / Trade-offs

- **[用户以为依赖包"打不开"]** → 3.3 要求在被排除目录内打开文件时明示边界;**"能打开却搜不到"必须是被解释过的行为,不是让用户自己猜**。
- **[名单漏掉某生态的重目录]**(如 Rust `target`、Python `.venv`) → 名单从一开始就带上常见几个;**MUST NOT 只放 `node_modules` 就收工** —— 那会让非 JS 用户在下一轮重复同一个惊喜。
- **[既有规模断言的数字会变]** → 排除后合成项目的索引数变化,**断言按新语义更新,不是把新行为往旧断言上凑**(4.6 已写死)。
- **[排除让用户错过真正想读的东西]** → 这正是"不静默 + 可展开 + 入口显眼"三条要一起满足的原因;缺任何一条,排除就从"帮忙"变成"替他决定"。
