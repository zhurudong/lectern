## Why

`add-tree-keyboard-nav`(已归档)的「目录树键盘导航」要求**容器获得焦点时活动行有确定落点**。实现不满足这条:`Tree.tsx` 的 `moveTo(0)` 会向后跳过所有非 node 行,**若容器获得焦点的那一刻整棵树还是"加载中…"占位,它扫到末尾找不到落点就返回;而 `onFocus` 只发生一次、不会重试** —— 活动行就永久为 `null`。

**用户影响很小**:`onTreeKeyDown` 在 `cur < 0` 时,`ArrowDown` / `Home` / `End` 都会落到第 0 行 —— **键盘不会死,按一下方向键即恢复**。

**但它是一处"spec 说 A、实现做 not-A"的偏离,而这份 spec 即将公开。** 我们整套对外叙事建立在"承诺可自证"上;**一条读得到、验得出、却不成立的 requirement,比没写它更伤** —— 它把"可验证"变成了"验了会发现我们说的不对"。

发现路径值得记:它是**验收收口时的一条偶发假红**暴露的 —— 夹具涨到 1.3 万文件后,树就绪变慢,才让这个一直存在的竞态显形。**在此之前它一直躲在"树够快"这个偶然条件后面。**

## What Changes

- 目录树 rows 就绪后,**若容器持有焦点且活动行仍为空,补设活动行**(落到首个可落点行)。
- 修的是**竞态**,不是把 `moveTo` 改宽松:`moveTo` 跳过非 node 行的行为是对的,问题在于**只在 `onFocus` 那一刻尝试一次**。

**不改任何行为契约** —— spec 已经写明该有确定落点,本 change 只是让实现追上它,故 `skip_specs: true`。

## Impact

- `src/tree/Tree.tsx` 一处;不碰 `src/intel/**`、不碰索引与预览。
- **不阻塞发货**:若用户决定在本 change 落地前 push,**必须在仓库中如实登记为已知问题**,MUST NOT 静默带过 —— 公开一条自己不满足的 requirement 而不声明,是"假绿的对外版本"。
