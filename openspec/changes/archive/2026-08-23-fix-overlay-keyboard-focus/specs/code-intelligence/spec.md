## ADDED Requirements

### Requirement: 临时浮层的键盘可操作性

凡因用户操作而弹出、且**需要用户从中做出选择**的浮层(多候选列表、引用结果、以及同类选择器),SHALL 可以**完全用键盘**完成整条动线:**进入 → 移动选择 → 确认 → 取消 → 焦点归还**。

**"能用键盘把它弹出来"不构成满足本要求** —— 若用户能用键盘触发浮层、却必须改用鼠标才能从中选择,**键盘链路就断在那里**,而这比根本没有键盘入口更容易被漏掉:入口是绿的,断的是入口之后。

具体地:
- 浮层出现时,焦点 SHALL 进入浮层并落在一个确定的初始项上;
- `↑` / `↓`(或等效方向键)SHALL 改变当前选中项,且**选中项必须可见**;
- 确认键 SHALL 对**当前选中项**生效;
- 取消键 SHALL 关闭浮层,并**把焦点归还到触发它的位置**,使用户能接着原来的动作继续;
- 浮层中的可选项 MUST 是键盘可达的 —— MUST NOT 只做成仅响应点击的元素。

**验收 MUST 走完整条动线。** 断言"浮层出现了"或"浮层内容正确"**不足以证明本要求成立** —— 那两者在"选不中任何一项"时同样为真。

#### Scenario: 键盘完成多候选选择

- **WHEN** 用户用键盘触发跳转,该名字有多处定义、弹出候选面板
- **THEN** 焦点进入面板并落在第一项;用 `↑↓` 可改变选中;确认后跳转到**当前选中的那一项**

#### Scenario: 键盘完成引用结果的选择

- **WHEN** 用户用键盘触发查找引用,引用面板列出结果
- **THEN** 用户可用键盘在结果间移动并激活其中一条,跳转到该处

#### Scenario: 取消后焦点归还

- **WHEN** 用户在浮层打开时按取消键
- **THEN** 浮层关闭,焦点回到触发它的位置,用户可继续原来的键盘动作,MUST NOT 被扔回页面开头
