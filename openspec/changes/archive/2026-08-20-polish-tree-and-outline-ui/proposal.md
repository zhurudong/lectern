## Why

用户真机试用后提了两条界面问题,并**追问过两次**:目录树的文件图标只有 📄 一个 emoji("难看"),大纲面板宽度写死不能拖。

这两条原本被归进 change #2 并压在"等 `add-code-intelligence` 归档"之后,而归档又在等用户做真机键位核验——用户明确说过那件事"不着急"。于是**用户在意的问题被排在了他本人不着急的事情后面**。PM 2026-08-20 纠正该门禁:规则的目的是保护专注度,不是把用户反馈变成排队叫号;前提变了,规则要重估。

拆出**与代码理解层零重叠**的这两条单独交付,不等归档。⌘ hover 高亮可跳转标识符要动 `CodeView` 与跳转查询路径,与待归档的 change 有重叠,继续留在 change #2。

## What Changes

- **文件类型图标**:去掉 emoji,换成内置的极简单色字形 + 按语言着色。
  - **去 emoji 是重点**:emoji 在不同系统字体下渲染不一致、饱和度高、与界面的克制风格打架 —— 这才是"难看"的主要来源,不是"图标太少"。
  - 目录用**中性色**;展开态**不换图标**(左侧已有三角 twisty 表达展开与否,两处表达同一件事是冗余)。
  - **两个主题分别验对比度** —— emoji 在明暗主题下长得一样,着色图标不会,这是最容易漏的一环。
  - 语言归类**复用 `src/lib/filetypes.ts` 的 `identifyByName`**,MUST NOT 新建第二张扩展名映射表。
- **大纲面板宽度可拖拽 + 持久化**:**复用 `src/app.tsx` 既有的 `.resizer` 那套机制**(拖拽 + clamp + localStorage),MUST NOT 写第二份拖拽逻辑。
  - 用户的抱怨本质是**不一致**(左边能拖、右边不能),不是"缺一个功能"。因此 spec 改成横跨所有面板分隔条的不变量,而不是给大纲单独加一条要求 —— 否则下一个新面板还会再漏一次。

- **补齐 SCSS / Sass / Less 的语法高亮**(用户反馈"不支持 SCSS")。
  - **并入本 change 而非另起,理由是耦合**:图标改动要按 `identifyByName` 的结果分配色类,SCSS 若不现在加,等加的时候图标那套还得再动同一批代码 —— **两次改同一个地方,不如一次做完**。没有这层耦合就该另起。
  - **实测确认零新增依赖**:`@codemirror/legacy-modes/mode/css` 直接导出 **`sCSS`** 与 **`less`** 两个**专用**模式,`mode/sass` 导出 `sass`(缩进语法)。因此**不需要"映射到 css + 标注精度边界"那条退路** —— 既然有专用模式,就不必制造一个需要向用户解释的近似。
  - **代码理解层不扩到 CSS 家族**:CSS 没有我们定义的"定义符号"概念,现状 CSS 也只有高亮没有跳转,SCSS 保持一致。MUST NOT 为"支持得更全"而破坏已明示给用户的"可跳转 / 仅高亮"分档。
  - 覆盖面盘点见 `docs/language-coverage-audit.md`(A–E 五组,待 PM 定取舍),**本 change 只做 A 组**。

**硬约束(继承)**:零网络(内置资源,不拉图标字体或远程资源)、不引入图标主题包(包体积)、只读、不碰 `src/intel/` 任何文件、不改任何已批准 requirement 的行为语义。

## Capabilities

### New Capabilities

(无)

### Modified Capabilities

- `file-preview`:「文件类型识别」与「代码语法高亮渲染」的语言清单增加 SCSS / Sass / Less。
- `file-tree`:「目录树排序与展示」增加**按文件类型区分**的图标要求与两主题对比度要求;「侧栏宽度调整」由"目录树与预览区之间的分隔条"**放宽为横跨所有相邻面板分隔条的不变量**(含大纲面板),消除"有的能拖、有的不能"的不一致。

## Impact

- `src/tree/Tree.tsx` + 新增 `src/tree/FileIcon.tsx`(按 `identifyByName` 的语言分类返回字形 + 色类)、`src/styles.css`(图标字形与两主题色板、大纲面板宽度改为可变)、新增 `src/lib/useResizable.ts`(左右两处共用的拖拽 + 持久化实现)、`src/app.tsx`(左侧分隔条改用该实现)。
- **实现期修正(2026-08-20)**:原写"在 `app.tsx` 接大纲分隔条",实际 `.preview-main` 在 **`src/preview/Preview.tsx`** 里,`app.tsx` 够不着,而分隔条必须插在预览区与大纲之间。落法:分隔条渲染在 `Preview.tsx`,宽度经 `.preview-main` 上的 **CSS 变量**下发给 `.outline` —— 这样 **`src/intel/OutlinePanel.tsx` 一个字不用改**,"不碰 `src/intel/**`"是硬满足而非勉强满足。代价是多碰了一个本清单没列的文件,但只加了一个分隔条元素与一个 style,未触及预览渲染逻辑。
- **不碰代码理解层的行为逻辑**(索引/跳转/引用/大纲/符号搜索)。**例外且仅有的一处**:2e 新增的第三档能力标识实现在 `src/intel/IntelBadge.tsx`(能力标识本就在那儿),改动 12 行、纯展示层。已核:`add-code-intelligence` 的「代码理解的支持范围与能力明示」要求"明示当前文件是否支持代码理解","近似高亮"档的说明中明写"不参与代码理解",该 requirement 仍满足,其 E2E 断言亦全绿。
  > 归档提示:`add-code-intelligence` 归档后,其 `code-intelligence` spec 的「能力明示」与本 change 在 `file-preview` 写的三档清单**描述的是同一枚徽标**,后续修改需同时看这两处。
- 体积:仅内置字形与 CSS,预期增量在 KB 量级。
- 验收:E2E 现有断言不得回归;新增断言见 tasks;并按新惯例做**真机截图前后对比**交给用户看。
