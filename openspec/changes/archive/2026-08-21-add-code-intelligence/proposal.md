## Why

现有查看器解决了"看得到"(目录树 + 语法高亮 + Markdown 渲染),但没有解决"读得懂":在陌生代码库里看到一个标识符,用户无法知道它定义在哪、被谁引用、这个文件里有哪些结构。而这正是竞品结构性缺失的格子 —— vscode.dev/github.dev 在**本地文件夹**场景下没有语言服务,跨文件导航基本失效且必须联网;原生 IDE 在临时机器/受管终端上装不动;Sourcegraph 类需要服务端。

需求侧同时在推:2026 年开发者角色从"作者"转向"审计者",读代码与验证代码的时长在涨,但工具仍全部围绕"写"设计。详见 `docs/prd-v0.2-reading-first.md`。本次变更交付 PRD 的 P0 层 —— **离线代码理解 + 全文搜索**,把产品从"浏览器里的文件预览器"推进为"零网络的本地代码阅读器"。

## What Changes

- **全项目符号索引**:打开项目后在 Web Worker 后台抽取定义符号(类型/函数/方法/字段/常量),不阻塞首屏、目录树、预览与既有 `⌘K` 文件名搜索;顶部展示索引进度与完成态。
- **跳转到定义(跨文件)**:对标识符触发跳转,打开目标文件并定位到定义行;P95 < 200 ms。**同名多候选时给候选列表,不静默猜一个**。
- **导航栈**:界面上的后退/前进按钮(主入口)+ macOS 的 `⌥←` / `⌥→`(补充键位,Windows/Linux 因 `Alt+←/→` 被浏览器后退/前进占用而不绑定)在跳转历史中回退与前进并恢复行位置,让"顺着调用链读下去"可回溯。
- **查找引用**:侧栏按文件分组列出符号在项目内的出现位置(排除注释与字符串),流式回填、点击直达行。
- **文件大纲(Outline)**:当前文件的结构列表,点击定位;Markdown 额外提供标题层级大纲。面板可折叠且状态保持。
- **全局符号搜索**:按符号名跨项目跳转,与仅搜文件名的 `⌘K` 界面上明确区分。键位仅 macOS 绑定 `⌘⇧O`;Windows/Linux 的 `Ctrl+Shift+O` 是 Chrome 书签管理器保留键,**不绑定也不提示**,该平台经界面入口使用。
- **全文内容搜索**:跨文件搜正文,结果流式回填、可点击直达行、可随时取消。键位仅 macOS 绑定 `⌘⇧F`;Windows/Linux 未经真机核验前不绑定不提示,经界面入口使用。
- **入口不依赖浏览器保留键**:每项能力都有一个不靠快捷键的界面入口(按钮 / 右键菜单 / 搜索面板模式切换),快捷键只是便捷层 —— `F12`(DevTools)、Win/Linux 的 `Ctrl+Shift+O`(书签管理器)、Win/Linux 的 `Alt+←`(浏览器后退)都是浏览器保留键,任一被抢占都不会让能力失效。各平台真实按键行为由 macOS + Windows 真机清单核验,不用 E2E 假绿断言充数。
- **单文件模式范围明确**:大纲提供;跳转限定文件内并引导"打开所在文件夹";查找引用与全局符号搜索不提供且在 UI 明示原因。
- **精度边界显式化**:代码理解 P0 只覆盖 Python / Java / C / C++ / Go / JavaScript / TypeScript(含 JSX/TSX);**UI 必须明示当前文件是否支持跳转**,不让用户靠试错推断。跳转与引用是基于符号名与语法树的启发式,不承诺编译级精确(不做类型推断、作用域解析、导入解析、宏展开)。
- **规模降级可见化**:单文件大小上限、符号总数上限、Worker 失败三类降级都有明确的用户可见提示,MUST NOT 静默失败或无提示地给出不完整结果。
- **预览新增按行定位**:上述所有导航入口共用一条"打开文件并定位到第 N 行 + 短暂高亮"的通道。
- **目录树刷新联动**:手动刷新目录树时符号索引同步重建,刷新后跳转/引用/大纲/符号搜索反映最新文件结构。
- **零新增运行时依赖**:复用项目已打包的 Lezer 语法树抽取符号,不引入 tree-sitter WASM(见 design.md 决策 D1),因此也不需要为 WASM 放宽 MV3 CSP。

不在本次范围(留给 change #2):P1 阅读者工作流(已读标记 / 书签笔记 / 阅读轨迹 / 导出 Markdown 导读)与 P2 隐私自证 UI + 上架素材。本次设计不为其埋阻塞:符号索引结构可序列化并已按文件记录内容指纹,书签与已读态所需的"文件 + 行"寻址由本次的按行定位通道统一提供。

## Capabilities

### New Capabilities

- `code-intelligence`: 不依赖语言服务器的离线代码理解 —— 符号索引、跳转到定义、导航栈、查找引用、文件大纲、全局符号搜索,以及支持范围明示与规模降级行为。
- `content-search`: 项目内全文内容搜索 —— 流式结果、直达行、可取消,以及搜索范围与降级边界。

### Modified Capabilities

- `file-preview`: 新增"按行定位与高亮"要求(所有跳转入口共用);修改"大文件降级"要求,增加截断文件的代码理解覆盖范围必须明示。
- `file-tree`: 修改"目录树刷新"要求,增加符号索引同步重建;修改"文件名快速搜索"要求,明确 `⌘K` 保持仅搜文件名,且与符号搜索、全文搜索三者并存不互相覆盖。

## Impact

**代码**
- 新增:`src/intel/`(符号抽取 Worker、索引 store、大纲面板、引用面板、导航栈)、`src/search/contentStore.ts` 与 `src/search/ContentPanel.tsx`(全文搜索)。**全文搜索复用符号 Worker 池的 `grep` 任务类型,不新建独立 Worker 文件** —— 独立 Worker 会把带五套 Lezer 语法的 349 KB chunk 整份复制一遍。符号搜索实现在 `src/search/SearchBox.tsx` 内的符号模式,不单独建文件。
- 改动:`src/preview/CodeView.tsx`(标识符 `Cmd/Ctrl`+点击、右键菜单、按行定位与高亮)、`src/state.ts`(选中项带目标行 + 导航栈)、`src/tree/treeStore.ts`(刷新联动索引重建)、`src/app.tsx` 与 `src/styles.css`(面板布局、新快捷键)、`src/lib/filetypes.ts`(标注哪些语言参与代码理解)。

**依赖**
- 新增 npm 运行时依赖:**0 个**。`@lezer/{python,java,cpp,go,javascript}` 已作为 `@codemirror/lang-*` 的传递依赖存在于 `node_modules`,仅需提升为 `package.json` 的显式 `dependencies`(锁定版本、避免被动升级)。

**产物体积**
- **实现后实测(2026-08-17,阶段二快照,收口时以最终产物重量)**:主 chunk 936,990 → 962,965 B(**仅 +2.8%**),五套 Lezer 语法全部落在独立的 `symbolWorker` chunk(345 KB),不进首屏关键路径;js/css 总量 950 KB → 1,333 KB,约 **+40%**,高于原估算 +26%,仍低于 PRD 的 50% 硬阈值。估算偏低因 Worker chunk 还需带 `@lezer/common`,且 Lezer 解析表是长字符串字面量、minify 压不动。

**manifest / 安全边界**
- 不新增任何 permission、不新增 host_permissions、不新增 CSP 指令(不引入 WASM,因此不需要 `wasm-unsafe-eval`)。

**验收**
- `scripts/e2e.mjs` 扩充代码理解与全文搜索断言,沿用 OPFS 合成项目惯例;现有 45 条断言 MUST 全绿,不得回归。
