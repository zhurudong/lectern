## 1. 实现

- [x] 1.1 `CodeView` 中监听修饰键按下/释放与指针移动,按住时对指针下的标识符取词
- [x] 1.2 查询**复用既有入口**:项目模式 `lookupDefinitions`,单文件模式复用 `jump.ts` 里那条本文件查询。**MUST NOT 新建第二条查询路径** —— 一旦提示与实际跳转走两套查询,二者迟早给出不同答案,而**那时提示会撒谎且没人发现**
- [x] 1.3 用 CodeMirror `Decoration` 施加提示样式;**仅在"指针下的标识符发生变化"时重算**,MUST NOT 每次 `mousemove` 都重建装饰(查表本身是微秒级,重建装饰不是)
- [x] 1.4 清除路径**三条都要**:释放修饰键、指针移出、**`window` 失焦 / `visibilitychange`** —— 第三条单独成立:按住修饰键 `⌘Tab` 切走时,**释放事件可能永不送达本页面**,只靠 keyup 会让提示滞留
- [x] 1.5 不支持代码理解的语言(仅高亮 / 近似高亮 / 纯文本)直接短路,不进入取词与查询
- [x] 1.6 **点击行为一行不改** —— 本 change 只加按住时的提示

## 2. 视觉

- [x] 2.1 两主题各定提示样式(下划线 + 变色),**与代码区既有元素同时出现时仍可分辨**
- [x] 2.2 **重点核对的是代码区、不是目录树**:提示会与 **`.cm-target-line`(跳转落点行:`--hot-bg` 底 + `--hot-bar` 左条,两者皆蓝)** 叠加 —— 刚跳转过去、落点行还亮着时,再悬停该行上的标识符,**同一行上会出现三个蓝色元素**。目录树的焦点环/选中态在**另一个面板**,与本提示不同屏共处,不是本条要看的对象
- [x] 2.3 区分手段沿用既有口径:**MUST NOT 再加一种颜色**,让它们在**形式维度**错开(整行底色 / 左侧实心条 / 字下划线)
- [x] 2.4 双主题自检并附图,**必须截"提示 + 落点行高亮同时出现在同一行"的样子**,不是分别截 —— 分别看是两张合格的图,合起来才是用户会看到的那一行

## 3. 验收

- [x] 3.1 E2E:可跳转标识符按住修饰键悬停 → 有提示 class;**不可跳转的 → 无 class**(两条都要,只验前者等于没验出"区别")
- [x] 3.2 E2E:释放修饰键 / 指针移开 → 提示清除
- [x] 3.3 E2E:**模拟窗口失焦** → 提示清除(这条最容易漏,也最容易在真机上被用户撞见)
- [x] 3.4 E2E:`.yaml` 等不支持语言无提示;单文件模式下本文件无定义的标识符无提示
- [x] 3.5 E2E:多处同名定义的标识符 → 悬停有提示、点击**仍弹候选列表**(证明提示没有把语义升级成确定跳转)
- [x] 3.6 **回归门禁**:既有全部断言全绿,尤其 `⌘`+点击跳转、多候选、导航栈那几组
- [x] 3.7 `npm run build` 与 `openspec validate --all --strict` 通过;`npm run check` 三类不变量仍全绿
