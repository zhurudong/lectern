## 1. 焦点模型(先做,后面两段都建在它上面)

- [x] 1.1 三个面板各建**一个可聚焦容器**(目录树已有;预览区与大纲要补),按 DOM 顺序(树 → 预览 → 大纲)排入**原生 Tab 序**
- [x] 1.2 面板级**焦点态可见**:哪个面板持有焦点要一眼看出,与 restyle 的焦点环口径一致(形式维度错开,**MUST NOT 再加一种颜色**)
- [x] 1.3 **不建全局键盘分发器** —— 每个面板的处理器挂在自己的容器上。**焦点归属就是路由**,不写"我现在在哪个面板"的条件判断
- [x] 1.4 E2E:纯键盘从目录树 → 预览 → 大纲循环一圈,每步断言焦点标识落在正确面板
- [x] 1.5 E2E:**基线独立成立** —— 断言不依赖任何自定义键位即可完成整圈(只用 `Tab` / `Shift+Tab`)

## 2. 三面板接入

### 2a. 预览区光标(**去掉一道冗余锁,不是加功能**)

- [x] 2a.1 移除 `EditorView.editable.of(false)`,**保留 `EditorState.readOnly.of(true)`**;加入光标移动 keymap(方向键 / PageUp/Down / Home/End / 选区扩展),**不引入任何编辑命令**
- [x] 2a.2 **放行条件一:证明那道锁确实冗余。** 逐条验证所有写入路径均不改变文档:键盘输入、粘贴、拖放、**输入法组合**、浏览器原生右键菜单的编辑动作。**既有「只读保证」Scenario 要扩到覆盖这些路径,不能只验"打字没反应"**
- [x] 2a.3 **放行条件二:contentEditable 打开后的附带面。** 实测浏览器拼写检查与 IME 组合框是否附着到代码区,观感与性能是否受影响;必要时关闭拼写检查
- [x] 2a.4 光标位置**可见**(只读态下也要能看出光标在哪)
- [x] 2a.5 E2E:方向键/翻页/行首行尾移动光标;**且**输入、粘贴、拖放后文档内容逐字不变

### 2b. 大纲键盘

- [x] 2b.1 大纲容器可聚焦,`↑` `↓` 选条目、`Enter` 定位 —— **模式照搬目录树**(容器唯一可聚焦 + `aria-activedescendant` + 活动项用**稳定标识而非列表下标**)
- [x] 2b.2 **先照搬模式,暂不抽公共组件**:树是层级+路径、大纲是平铺+符号,**过早抽象会造出一个两边都不合身的中间层**。实现后若键盘逻辑确实近乎一致再抽 —— **抽象要由重复驱动,不由预感驱动**
- [x] 2b.3 活动条目可见;切换预览文件后大纲重建,**活动态不指向不相干的条目**
- [x] 2b.4 E2E:键盘选条目 + Enter 定位;切文件后活动态不错位

## 3. 键位落地(**最后做,因为它依赖真机核验**)

- [x] 3.1 **先把候选键位登记进 `docs/manual-verification.md` 并真机核验,再写代码。** 已知禁区:`F6`(聚焦地址栏)、`Mod+数字`(切标签页)、`F12`(DevTools)、**`Mod-Shift-B`(Windows 显示书签栏)**。**MUST NOT 因为某键位是主流 IDE 惯例就跳过核验 —— IDE 不在浏览器里跑,它们的约定不携带浏览器的占用信息**
- [x] 3.2 键盘触发**跳转到定义**:绑在预览区容器/CM6 keymap 上(**只在代码区持有焦点时生效**),复用 `definitionsFor` + `navigateWithHistory`,**MUST NOT 新建第二条查询或导航通道**
- [x] 3.3 键盘触发**查找引用**:同上,复用既有引用通道
- [ ] 3.4 "切换面板"的**便捷键位**(可选):基线是 Tab,此项只作改善;**核验不过就不做,不得因此削弱基线**
- [x] 3.5 所有落地键位的核验结论回填 `docs/manual-verification.md`(**验证人 / 平台 / 日期**),未验平台按保守假定**不绑定也不提示**

## 3b. 可发现性(**做了快捷键而用户不知道,等于没做**)

- [x] 3b.1 **键位定义只有一处**:导出一份"操作 → 键位"的单一映射,**实际绑定与界面标注都从它取**。**MUST NOT 在菜单或帮助面板里另手写键位文本** —— 两份各写,改键位时界面会说谎,**而说谎那一刻两边都不报错**
- [x] 3b.2 预览区右键菜单的"跳转到定义""查找引用"**旁注对应键位** —— 鼠标用户在用鼠标的那一刻看到键盘的存在,**这是最不打扰的教学时机**(IDE/编辑器标准做法)

- [x] 3b.4 帮助入口的**基线是界面上可点的入口(如 `?` 按钮),不依赖任何自定义键位**;`⌘/` 之类 MAY 叠加,但**需先真机核验才写死**(照 3.1 的规矩,别再制造一次阻塞)
