## Why

用户的诉求不是五个零散功能,是**一件事**:**读代码时手不离键盘。**

现状是"半条链路":目录树已能纯键盘操作(`add-tree-keyboard-nav`),但**一旦打开文件就断了** —— 代码区光标动不了、跳转要 `⌘`+点击、查引用只有右键菜单、大纲只能鼠标点、三个面板之间无法用键盘互相切换。**于是键盘导航止步于"选中一个文件",而读代码真正的动作全在那之后。**

齐了之后的目标链路:**浏览目录 → 打开文件 → 在代码里移动 → 跳定义 → 查引用 → 回来**,全程不碰鼠标。

## What Changes

**一个主题,五个部分**(MUST 作为整体设计,不零散加 —— 零散加必然长出五套互不一致的键位):

1. **三面板焦点切换**:目录树 ↔ 预览区 ↔ 大纲。
2. **预览区光标键盘移动**:↑↓←→ / PageUp / PageDown / Home / End 在只读代码里移动光标与选区。
3. **键盘触发跳转到定义**:光标停在标识符上按键跳转(现在只有 `⌘`+点击与右键菜单)。
4. **键盘触发查找引用**:同上。
5. **大纲键盘操作**:↑↓ 选条目 + Enter 定位(现在只有鼠标)。

**贯穿要求**:
- **键位成体系**,不是各加各的;
- **焦点态全程可见**(哪个面板、哪一行/哪个条目持有焦点),与 restyle 的焦点环口径一致;
- **所有新键位避开浏览器保留键**,并**逐条进 `docs/manual-verification.md` 真机核验**;
- **每项能力保留非键盘入口**(既有的点击/右键菜单不动)—— 沿用"键盘是便捷层、界面入口保底"的既定口径。
