## Why

界面文案目前全中文、且直接写死在各组件里。这把受众钉死在中文开发者;而 Lectern 的产品定位(零网络、只读的本地代码阅读器)对全球开发者都成立 —— 英文 UI 是"扩大受众"最直接的一步。本次**只做机制与样板**,不整片翻译:先把 i18n 骨架立起来、转一个面板做样板证明可行,交 PM 审过选型与默认策略后再分批迁移其余文案。

## What Changes

- **新增轻量 i18n 机制** `src/i18n/`(`index.ts` + `messages.ts`),与 `theme.ts` 同风格:一个 `lang` 信号 + `localStorage` 持久化,**零第三方库**。
  - `t(key, params?)`:key→翻译表查文案,支持 `{name}` 占位符插值。
  - **在渲染期读 `lang` 信号** → 任何在渲染中调用 `t()` 的组件自动订阅,切换语言即时重渲染(与主题切换同机制,不需额外接线)。
  - **回退链**:当前语言 → 中文 → key 本身。缺英文键不空白、不崩溃,显示中文原文 —— 让"逐面板迁移"成为安全增量。
- **顶栏新增语言开关**(样板)`EN` / `中`,`toggleLang()`;是语言切换的最终归宿(与主题开关并排)。
- **转一个样板面板:入口页 `Welcome`**。它自足、可见度高,且含相对时间这类**带占位符**的动态串,能一并证明插值路径。切换开关即可看到入口页在中↔英之间即时切换。
- **CJK 字体栈不动**:语言切换只改文案,不动 `styles.css` 的字体声明;`<html lang>` 随之更新(供无障碍/截图诊断)。

## Non-goals(本次明确不做,等 PM 审方案后再批量推)

- **不整片翻译其余面板**:顶栏其余按钮、目录树、预览区能力标识、大纲/引用/搜索面板、键盘帮助、跳转提示、进度与降级文案等 ~200 处仍是中文,留待方案批准后按 tasks.md 分批迁入 `messages.ts`。
- 不做复数规则库、日期/数字本地化框架(相对时间用简单占位符即可;`toLocaleDateString` 已随浏览器区域走)。
- 不做第三方 i18n 库(i18next 等):当前规模用不上,且与"零依赖、可自证"的项目取向相悖。

## 待 PM 裁定的选型点

1. **默认语言策略**:现默认中文;浏览器语言探测已实现但由 `DETECT_BROWSER_LANG` 开关**关着**(理由:目前只有样板翻了英文,此刻让非中文浏览器默认英文会得到"英文入口页 + 中文其余"的割裂体验)。建议:英文覆盖达标后再把开关置 true,让非 `zh-*` 浏览器默认英文。
2. **key 命名与分组**:采用 `面板.用途`(如 `welcome.openFolder`);是否要更细的层级留待批量迁移时定。
3. **语言开关位置**:样板放在顶栏(与主题开关并排)。确认即可。

## Capabilities

### New Capabilities

- `localization`:界面文案的多语言机制 —— 语言选择与持久化、`t()` 取词与占位符插值、缺键回退、语言切换即时生效,以及"字体栈不随语言变"的约束。

## Impact

**代码**
- 新增:`src/i18n/index.ts`(机制)、`src/i18n/messages.ts`(zh/en 翻译表,当前仅 welcome.* + topbar.lang*)。
- 改:`src/app.tsx`(顶栏加语言开关按钮,仅此按钮走 `t()`)、`src/welcome/Welcome.tsx`(全部可见文案改走 `t()`,含相对时间插值)。
- 其余组件**本次不改**。

**字符串清单(供批量迁移排期)**
- 用户可见文案站点:`.tsx` 视图约 **151** 处,含 `.ts`(标签/提示/进度/帮助键位/种类标签等)约 **221** 处(排除注释后的粗测;逐面板迁移时以实际抽取为准)。
- 分布密集处:`Preview.tsx`(~20)、`OutlinePanel.tsx`(~16)、`SearchBox.tsx` / `ContentPanel.tsx`(各 ~14–15)、`Welcome.tsx`(~15,本次已转)、`Tree.tsx`(~13)、`app.tsx`(~13)、`keys.ts`(~16 动作标签,喂给帮助面板与右键菜单)、`symbols.ts`(15 个 `KIND_LABEL`)、`filetypes.ts`(语言/纯文本标签)、`IntelOverlay.tsx` / `ReferencePanel.tsx` / `IntelBadge.tsx`(各 ~9–11)。
- 需**占位符插值**的动态串:相对时间、索引进度(`已索引 N 个文件`)、大文件截断(`文件过大(N MB)…`)、引用计数等 —— 机制的 `{name}` 插值已覆盖此类。

**工作量估计(批量迁移,机制已就绪后)**
- 抽取 + 建 key + 双语填表:~221 处,按面板分 ~10 批,**约 1.5–2.5 人日**(翻译本身是主要成本;机制接线每处仅 `'串' → t('key')`)。
- E2E:现有断言大量按**中文可见文案**匹配(如 `扫描完成`、`可跳转`、`已达上限`)。批量迁移时这些断言要改为语言无关(锁定 `lang='zh'` 跑,或改用稳定 class/`data-*` 而非文案)——**这部分与翻译本身相当或更重**,约 **1–1.5 人日**,建议迁移时同步做,否则会大面积假红。
- 合计粗估 **3–4 人日**,可按面板增量交付、逐批过门禁。

**门禁(本次)**
- `npm run build` + `npm run check` 通过;全套 E2E 绿(默认中文,渲染输出与迁移前逐字一致,不触发既有文案断言回归)。
