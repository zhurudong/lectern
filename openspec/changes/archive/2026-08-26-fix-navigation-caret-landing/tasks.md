## 3. 验收(**断言纪律:验落在哪,不验动没动**)

- [x] 3.0 **夹具硬要求:目标符号 MUST 离文件开头足够远**(至少数十行)。
  > **这条不加,整组验收会全程绿着骗过我们。** 已实测的规律是:**跳转后 caret 恒在文档开头(第 1 行 @0),与目标行无关**;所以只要夹具文件够小、定义恰好在第 1 行,"caret 落在目标行"就**碰巧成立**,断言全绿而缺陷隐身。独立测量里就有一格是这么"通过"的(两个三行的同名夹具文件)。
  > **推论:凡"位置正确性"类断言,夹具的正确答案 MUST NOT 与默认值重合** —— 否则它测的是默认值,不是正确性。
- [x] 3.0b **"可续"要按落点所在区域分开判,MUST NOT 压成一列**:
  - **落在代码区**的入口 → 判据是"不动光标直接按 `⌘⇧↩`,引用面板出不出";
  - **落在结果列表**的入口(引用/全文,焦点有意留在列表)→ 判据是"在列表里还能继续上下挑" —— **与前者不是同一件事**,同一列里放两种语义会让"✓"失去含义。

- [x] 3.0c **回程夹具:离开时的 caret MUST NOT 在视口顶行**(同一陷阱的第三次出现)
  > 记录离开位置用的是**视口顶行**。若夹具里"用户离开时 caret 恰好在视口第一行",那么 `viewportLine == caret 行`,**回退落点碰巧正确,断言绿,缺口隐身** —— 与 3.0 是同一个形状:**样本替被测对象把答案凑对了**。
  > 因此回程夹具 MUST 构造成:**先滚动、再把 caret 放到视口中部某行**(caret 行 ≠ 视口顶行),然后跳走、`⌥←` 回来,断言**回到的是 caret 那一行,不是当初的视口顶行**。
  > **这个形状已经在本 change 里出现三次**(小文件 / 单一目标行 / 视口顶行)。**判据固定下来:写任何"位置正确"的断言前,先问"如果被测代码什么都不做,这条断言会不会照样绿"。** 会,就是夹具的问题,不是断言的问题。

- [x] 3.0d **夹具自检必须是一条断言,MUST NOT 只是嘱咐**(3.0 的下一环,由独立测量侧实证)
  > 3.0 要求"目标符号离文件开头足够远",**但那只约束了写夹具的人的意图,没有任何东西检查夹具真的长成那样**。实证:独立测量装置因字符串转义写错,注入的样本文件里全是字面量 `\n`、**整个文件只有一行**,而装置照跑不误、给出一片"跳转全线崩溃"的红 —— **若那份数据被采信,我们会拿一个幻影去改真代码。**
  > 因此 E2E **MUST 在使用夹具前先断言夹具自身的形状**:至少校验**总行数**与**目标符号所在行号**,不满足即判失败并打印实际值,**MUST NOT 继续往下跑**。
  > **一般化:凡"精心构造的前提"都要有一条断言证明它真被构造出来了。** 3.0 防的是「答案与默认值重合」,这条防的是「**夹具根本不是你以为的样子**」—— 后者更靠前:**夹具没造成功时,3.0 那条约束等于没写。**
- [x] 3.0f **反证:去掉修复后重跑,主断言 MUST 转红而前提断言 MUST 仍绿**(终审门槛,标准做法)

## 6. 真机(冻结 `dist`)复验暴露:全文面板关闭仍落 `body`

- [x] 6.1 **根因(方案会话已定位,非"发起者没传")**:`useOverlayKeyboard` 用 `activatedRef` 表示"本次关闭由激活引起,跳过通用归还";它在 `open` 变化的 effect 里复位,**而 `ContentPanel` 传的是常量 `open: true`** —— effect 只在挂载时跑一次。
  > 于是:**激活一次之后,该标记永久为真。** 全文面板是**唯一一个"激活之后不关闭"的浮层**,所以只有它会让标记残留到下一次关闭 —— 候选/引用面板激活即卸载,标记随之消失。
  > **修法约束:该标记 MUST 描述"这一次关闭事件的成因",MUST NOT 描述"这个面板历史上发生过什么"。** 对"激活后仍保持打开"的浮层,标记必须在该次激活处理完毕后立即复位(或改为由"是否会因激活而关闭"显式声明)。
- [x] 6.2 **E2E 那条断言是假绿:它的动线里没有"激活"这一步**
  > 现有用例:搜索 → 直接 `focus()` 到 `.ref-body` → `Esc`。**从不激活任何一项**,所以 `activatedRef` 始终为假,归还照常执行,断言绿。
  > **真机动线多了关键一步**:搜索 → **选中一条跳过去** → 面板仍开着 → `Esc`。
  > 要求:该断言 MUST 改为**先激活一条结果、再按 `Esc`**;**并额外保留一条"未激活直接 Esc"的用例** —— 两条动线的成因不同,MUST NOT 用一条代替另一条。
- [x] 6.3 **同类排查**:任何"激活后不关闭"的浮层都受同一影响。逐一确认哪些浮层属于此类,**MUST NOT 只改 ContentPanel 一处**
- [x] 6.4 **反证改做全文面板那两条(裁定采纳 (b))**:临时恢复"激活历史导致关闭跳过归还"的旧语义后,"先激活再 Esc" 唯一转红,"未激活直接 Esc" 仍绿(`324/325`);证明两条动线各测各的。正确实现下两条连续 4 轮稳定。
  > **候选那条不能用于反证** —— 它当前约 1/4 概率变红,**用一条偶发断言做单轮因果判断,得到的结论没有信息量**。这是"概率性的绿"的镜像:**概率性的红同样不能当证据。**
- [x] 6.5 **必须先判定:候选那条的偶发是不是本轮改动引入的**(这决定要不要发)
  > 两种可能后果完全不同:**① 早已存在** → 与本 change 无关,单独追踪,不阻塞发布;**② 本轮引入** → 那是**用户可见的间歇性回归**(候选面板偶尔不获得焦点 = 键盘走到死路),属于我们这一族的缺陷,**不能带着发**。
