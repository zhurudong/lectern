## Why

目录树**完全不能用键盘**:`src/tree/Tree.tsx` 里 `onKeyDown` / `tabIndex` / `role` 一个都没有,所有导航必须用鼠标点。对一个定位为"代码阅读器"的工具,这是硬缺口——读代码的人手在键盘上,为了换个文件就得摸鼠标,阅读节奏被打断。

用户真机使用后提出,且**明确要求这条先做先发**,不与视觉升级同批。

## What Changes

按 **WAI-ARIA `tree` 模式**实现目录树键盘导航(不自创一套键位):

- `↑` / `↓`:在**当前可见行**之间移动活动行(跨已展开层级,虚拟滚动下同样正确)
- `Enter`:文件 → 在预览区打开;目录 → 展开/折叠切换
- `→`:目录未展开 → 展开;目录已展开 → 移到第一个子项;文件 → 无操作
- `←`:目录已展开 → 折叠;目录已折叠或文件 → 移到父目录
- `Home` / `End`:移到首行 / 末行
- **活动行必须有可见的焦点标识**,且与"选中态"在视觉上可区分(两者是不同概念:活动行是键盘位置,选中是当前预览的文件)
- 活动行被键盘移出视口时 SHALL 自动滚回可见区域
- **焦点管理不与其他输入区打架**:搜索框(`⌘K`)或其他输入获得焦点时,方向键 MUST NOT 被目录树截走

**不做**:自定义键位映射、多选、拖拽、重命名等编辑类操作(只读定位不变)。

## Capabilities

### Modified Capabilities

- `file-tree`:新增「目录树键盘导航」要求 —— 键盘可完成选中/展开/折叠/打开的完整链路、活动行可见且可滚回视口、虚拟滚动下焦点不丢、与其他输入区的焦点互不抢夺。

## Impact

- `src/tree/Tree.tsx`(容器级 `role=tree` + `tabIndex` + `onKeyDown` + 活动行状态)、`src/tree/treeStore.ts`(可能需要"按可见行索引取节点 / 取父节点"的辅助)、`src/styles.css`(焦点标识样式,两主题各一套)。
- **不碰** `src/intel/**` 与预览渲染逻辑。
- 与视觉升级(A 方案)**都会碰 `Tree.tsx`**,故本 change **先做完并发布**,视觉紧随,避免同时改同一文件。
