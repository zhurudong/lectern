> **首发切分(规格阶段 2026-08-23 裁定)。** 本组有一个**硬依赖链,不能任意拆**:
> - **`Escape` 关闭(1.1)可以独立成立** —— 面板此刻是非模态的(`aria-modal` 已按勘误删除),不声明任何未实现的东西;
> - **焦点陷阱(1.3)MUST NOT 先于 `Escape`(1.1)落地** —— **没有出口的焦点陷阱就是真的把人困住**,那比现状糟得多;
> - **`aria-modal`(1.4)MUST NOT 先于焦点陷阱(1.3)** —— 否则又回到"声明在前、实现在后";
> - **焦点移入(1.2 前半)与归还(1.2 后半)必须同时做** —— 只移入不归还,用户关闭后会被扔在面板残骸的位置上。
>
> **因此首发底线 = 1.1 + 2.1(其余为增强,可后补)。** 理由:1.1 是键盘用户打开面板后的第一反应键,成本几分钟;而 1.2/1.3/1.4 是"把它做成规范模态"的一整包,**拆开做反而制造更糟的中间态**。

## 1. 实现

- [x] 1.1 **【首发底线】** `Escape` 关闭帮助面板
- [x] 1.1b **【首发底线】** 把「`Esc` 关闭本面板」列进帮助面板本身(经 `keys.ts` 单一映射,天然同源)。**裁定:`needsVerification: false`** —— 该字段的含义是"**此键位是否可用尚不确定、需真机核验**",而 `Esc` 关对话框是**通用约定,不与浏览器键位竞争**,可用性不存在疑问。
  > **为什么不推迟到 1.2 那一包**:`Esc` **现在就生效**,列出来现在就是准确的;而**一块"讲解键盘操作"的面板,却不写自己的退出键**,正是我们刚被咬过的那个形状 —— **功能与它自身可用性之间的缝**。推迟等于明知有缝还发一版。
- [ ] 1.2 **【增强·可后补】** 打开时焦点移入面板;关闭后**还回触发按钮**(`.help-toggle`)
- [ ] 1.3 **【增强·可后补】** 打开期间 `Tab` / `Shift+Tab` 在面板内循环,焦点不逸出
- [ ] 1.4 **【增强·可后补】** **仅当 1.3 成立后**才重新加回 `aria-modal="true"`;不成立就不加 —— **MUST NOT 再出现"声明在前、实现在后"**
