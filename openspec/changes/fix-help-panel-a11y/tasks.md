> **首发切分(规格阶段 2026-08-23 裁定)。** 本组有一个**硬依赖链,不能任意拆**:
> - **`Escape` 关闭(1.1)可以独立成立** —— 面板此刻是非模态的(`aria-modal` 已按勘误删除),不声明任何未实现的东西;
> - **焦点陷阱(1.3)MUST NOT 先于 `Escape`(1.1)落地** —— **没有出口的焦点陷阱就是真的把人困住**,那比现状糟得多;
> - **`aria-modal`(1.4)MUST NOT 先于焦点陷阱(1.3)** —— 否则又回到"声明在前、实现在后";
> - **焦点移入(1.2 前半)与归还(1.2 后半)必须同时做** —— 只移入不归还,用户关闭后会被扔在面板残骸的位置上。
>
> **因此首发底线 = 1.1 + 2.1(其余为增强,可后补)。** 理由:1.1 是键盘用户打开面板后的第一反应键,成本几分钟;而 1.2/1.3/1.4 是"把它做成规范模态"的一整包,**拆开做反而制造更糟的中间态**。

## 1. 实现

- [x] 1.1 **【首发底线】** `Escape` 关闭帮助面板
- [x] 1.1b **【首发底线】** 把「`Esc` 关闭本面板」列进帮助面板本身(经 `keys.ts` 单一映射,天然同源)。**裁定:`needsVerification: false`** —— 该字段的含义是"**此键位是否可用尚不确定、需真机核验**",而 `Esc` 关对话框是**通用约定,不与浏览器键位竞争**,可用性不存在疑问。
  > **为什么不推迟到 1.2 那一包**:`Esc` **现在就生效**,列出来现在就是准确的;而**一块"讲解键盘操作"的面板,却不写自己的退出键**,正是我们刚被咬过的那个形状 —— **功能与它自身可用性之间的缝**。推迟等于明知有缝还发一版。
- [x] 1.2 打开时焦点移入面板;关闭后**还回触发按钮**(`.help-toggle`)。
  > 焦点的移入与归还**复用 `useOverlayKeyboard`**(候选/引用/全文三处同一份),不在这里重写 ——
  > 那段被两个真实缺陷咬过(卸载时 `contains` 恒假 → 一次都不归还;放宽判据后 → 在别人接管焦点之后抢回来)。
  > 但**没有复用它的列表键位映射**:那份 `onKeyDown` 对 ↑↓/Home/End 一律 `preventDefault()`,
  > 而本面板是一块可滚动长文,吞掉方向键就等于让它滚不动。所以 `count: 0`,按键自己写。
- [x] 1.3 打开期间 `Tab` / `Shift+Tab` 在面板内循环,焦点不逸出(容器 `tabIndex={-1}`,焦点在容器上时正向从首项、反向从末项起)
- [x] 1.4 1.3 成立**之后**才把 `aria-modal="true"` 加回来。顺序没有反过来:陷阱先落地并被 2.2 验过,声明才回来

## 2. 验收

- [x] 2.1 **【首发底线】** E2E:键盘打开 → `Escape` 关闭 → 断言**焦点回到 `.help-toggle`**。**"面板关了"不算过** —— 焦点去哪了才是键盘用户在意的
- [x] 2.2 E2E:面板打开后 `Tab` ×6 + `Shift+Tab` ×3(**共 9 步,且正反两向都走**),每一步都断言
  `document.activeElement` 仍在面板内。按到超过可聚焦元素个数的圈数,验的是**循环**而不是"碰巧还在里面";
  反向单列是因为"从第一个元素往回走"是最容易漏出去的那一步。
- [x] 2.3 E2E:断言 `aria-modal` 与焦点约束**互为背书**,取双向强形式(`aria-modal="true"` **且** 9 步全程被约束)。
  > 只写"声明了就必须约束"不够 —— 那条在 `aria-modal` 被误删时照样绿;而 1.3 已落地,此刻少了声明
  > 就是"做了却不告诉辅助技术"。反过来若哪天陷阱被拆,这条也红,不会留下一个孤零零的声明。
- [x] 2.4 **回归门禁**:全套 **331/331 PASS**,零 FLAKY(断言数 327 → 331)
- [x] 2.5 `npm run build` 绿 / `npm run check` 绿(不变量 + 语言覆盖)/ `openspec validate --all --strict` **9 passed 0 failed**

归还才有东西可归还。
