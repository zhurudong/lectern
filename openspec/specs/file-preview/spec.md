# file-preview Specification

## Purpose

负责文件内容的识别与渲染:按文件类型分发到代码高亮、Markdown 富文本、图片预览等渲染通道,并对二进制文件与超大文件做安全降级,提供接近 IDE 的只读阅读体验。
## Requirements
### Requirement: 文件类型识别

查看器 SHALL 依据文件扩展名识别文件类型并选择渲染方式。对**无扩展名或以整文件名标识**的常见文件(如 `Dockerfile`、`CMakeLists.txt`、`Makefile`),查看器 SHALL 先按**整文件名**匹配再回退到扩展名匹配。两者都不命中时 SHALL 进行内容嗅探:文本内容按纯文本展示(可结合 shebang 识别脚本语言),疑似二进制内容走二进制降级。

#### Scenario: 常见语言识别

- **WHEN** 用户打开 `.md` / `.py` / `.java` / `.c` / `.cpp` / `.go` / `.js` / `.ts` / `.json` / `.html` / `.css` / `.scss` / `.sass` / `.less` / `.sql` / `.yaml`(含 `.yml`)/ `.xml` / `.sh` / `.rs` / `.rb` / `.kt` / `.cs` / `.gradle` / `.groovy` / `.toml` 等扩展名的文件
- **THEN** 预览区以对应语言的语法高亮(或对应渲染通道)展示内容

#### Scenario: 按整文件名识别

- **WHEN** 用户打开 `Dockerfile` 或 `CMakeLists.txt`(前者无扩展名)
- **THEN** 预览区以对应语言的语法高亮展示,而非落入纯文本

#### Scenario: 未知扩展名的文本文件

- **WHEN** 用户打开无扩展名且不在整名清单中、但内容为文本的文件(如 `LICENSE`)
- **THEN** 预览区以纯文本(含行号)展示,不报错

### Requirement: 代码语法高亮渲染

代码文件 SHALL 以只读模式渲染,包含语法高亮与行号。渲染 SHALL 保持原始内容逐字呈现,MUST NOT 修改或重排文件内容。

高亮能力 SHALL 分为以下**两档**(本要求只管高亮;**文件的代码理解能力是另一个维度**,由代码理解的能力标识负责明示,二者 MUST NOT 混为一档):

- **专用高亮**:Python、Java、C、C++、Go、JavaScript、TypeScript(含 JSX/TSX)、Rust、PHP、Markdown、JSON、HTML、CSS、SCSS、Sass、Less、SQL、YAML、XML、Shell、Ruby、Kotlin、C#、Groovy(含 `.gradle`)、TOML、Dockerfile、CMake。
- **近似高亮**(借用相近语言的高亮通道,准确性不保证):Vue、Svelte(借用 HTML 高亮,`<script>` / `<style>` 块可高亮,模板指令如 `v-if` / `{#if}` 不保证准确)。

查看器 SHALL 让用户在预览时知道以下两件事,**至于界面用哪些词来表达、共有几个标签,由实现决定,本要求 MUST NOT 被理解为对展示文案的枚举**:

1. **该文件的高亮是专用的还是近似的** —— 近似 MUST 被标注为近似,MUST NOT 让用户以为是该类型的专用高亮;有专用模式可用的类型 MUST NOT 以近似充当。
2. **该文件是否参与代码理解**(可跳转 / 仅大纲 / 不参与)—— 具体档位与措辞由代码理解的能力明示要求规定。

**两档之外的类型 SHALL 以纯文本(含行号)展示**。以下是**常见类型中当前明确不覆盖**的部分(该清单是常见项的举例,**并非穷举** —— 未列出 ≠ 已覆盖):Swift、Dart、Lua、Scala、R、Perl、PowerShell、Protobuf、GraphQL、Terraform/HCL,以及 Makefile(无可用的专用高亮模式,按纯文本展示但保留正确的文件图标)。此清单为**当前的明确边界**而非待办 —— 对外说明 SHALL 表述为"当前覆盖 X、不覆盖 Y",MUST NOT 表述为"尚未支持"或"以后补齐"。

#### Scenario: 高亮渲染 Go 文件

- **WHEN** 用户打开一个 `.go` 文件
- **THEN** 关键字、字符串、注释等以不同样式高亮,左侧显示行号,内容与磁盘文件逐字一致,能力标识显示为"可跳转"

#### Scenario: 高亮渲染 SCSS 文件

- **WHEN** 用户打开一个含嵌套规则、`$` 变量与 `@mixin` 的 `.scss` 文件
- **THEN** 这些 SCSS 特有语法被正确高亮(而非当作纯文本或仅按 CSS 近似处理),能力标识显示为"仅高亮"

#### Scenario: 近似高亮必须明示

- **WHEN** 用户打开一个 `.vue` 文件
- **THEN** `<script>` 与 `<style>` 块获得高亮,且界面**明确标注该文件为近似高亮**,用户不会误以为这是 Vue 专用高亮

#### Scenario: 明确不覆盖的类型

- **WHEN** 用户打开一个 `.swift` 或 `Makefile`
- **THEN** 预览区以纯文本(含行号)正常展示,文件图标正确,界面不声称提供该语言的高亮

#### Scenario: 只读保证

- **WHEN** 用户在预览区尝试输入或修改文本
- **THEN** 内容不发生变化(允许选择与复制)

### Requirement: Markdown 双模式渲染

Markdown 文件 SHALL 默认以富文本渲染(标题、列表、表格、链接、代码块等),代码块内按其声明语言高亮;用户 SHALL 能在"渲染视图"与"源码视图"之间切换。富文本渲染 MUST 对 HTML 内容做净化,防止脚本注入。

#### Scenario: 渲染视图与源码切换

- **WHEN** 用户打开 `README.md` 并点击视图切换按钮
- **THEN** 预览区在富文本渲染与带高亮的源码视图之间切换,再次点击可切回

#### Scenario: 恶意内容净化

- **WHEN** Markdown 文件中包含 `<script>` 或内联事件处理器等可执行内容
- **THEN** 渲染结果中这些内容被移除或转义,不被执行

### Requirement: Markdown 相对资源处理

在项目(目录)上下文中渲染 Markdown 时,相对路径图片 SHALL 通过目录句柄解析为本地内容展示;解析失败或处于单文件模式(无目录上下文)时 SHALL 展示占位符而非裂图。相对路径链接指向项目内文件时,点击 SHALL 在查看器内打开该文件;无法解析的相对链接 SHALL 置为不可用。远程(http/https)图片 MUST NOT 自动加载,以占位符代替;外部链接允许用户点击后在新标签页打开。

#### Scenario: 相对路径图片解析

- **WHEN** 项目内 `README.md` 引用 `![](docs/img.png)` 且该文件存在
- **THEN** 渲染视图中该图片正常显示(经本地句柄读取,无网络请求)

#### Scenario: 资源缺失或单文件模式降级

- **WHEN** 相对图片路径无法解析(文件不存在,或以"打开文件"方式打开、无目录上下文)
- **THEN** 图片位置展示占位符,页面其余部分正常渲染,不报错

#### Scenario: 相对链接项目内导航

- **WHEN** 用户点击指向项目内其他文件的相对链接(如 `[说明](../CONTRIBUTING.md)`)
- **THEN** 查看器在预览区打开目标文件,目录树选中态同步

### Requirement: 主题切换

查看器 SHALL 在右上角提供浅色/暗色主题切换,默认浅色;切换即时生效,作用于整体界面、代码高亮与 Markdown 渲染,选择 SHALL 在后续会话中保持。两种主题下内容均 SHALL 保持可读的对比度。

浅色与暗色 SHALL 是**各自独立调校的完整色板**,MUST NOT 用"同一组颜色叠加透明度/滤镜"的方式从其中一套推导出另一套 —— 那会让其中一套的对比度不受控。

**语法高亮色板 SHALL 随主题成套切换**:主题切换后,代码区的关键字/字符串/注释/类型等着色 MUST 与当前主题属于同一套设计,MUST NOT 出现"界面已切换而代码区仍是另一套配色"的状态。

界面中的状态变化(选中、悬停、展开/折叠等)SHALL 有短暂过渡而非瞬变;过渡 MUST NOT 长到延迟用户对操作结果的感知。

界面所用字体 MUST 全部来自本机可用字体或扩展内置资源,**MUST NOT 引用任何远程字体资源** —— 这是零网络承诺的一部分,与是否好看无关。

#### Scenario: 切换到暗色主题

- **WHEN** 用户点击右上角主题切换选择暗色
- **THEN** 界面、代码高亮与 Markdown 渲染即时切换为暗色配色,重新打开查看器时仍为暗色

#### Scenario: 默认浅色

- **WHEN** 用户首次安装扩展并打开查看器
- **THEN** 界面为白底浅色主题

#### Scenario: 语法高亮随主题成套切换

- **WHEN** 用户在打开着一个代码文件时切换主题
- **THEN** 代码区的关键字/字符串/注释等着色同步切换到该主题对应的那一套,不出现界面与代码区分属两套配色的中间状态

#### Scenario: 状态变化有过渡

- **WHEN** 用户在目录树中悬停、选中一行,或展开一个目录
- **THEN** 视觉状态以短暂过渡完成而非瞬间跳变,且不产生可感知的操作延迟

#### Scenario: 字体不外联

- **WHEN** 用户在任意主题下浏览任意文件
- **THEN** 页面不发起任何字体相关的网络请求,文本以本机可用字体或扩展内置字体渲染

### Requirement: 图片与二进制降级

常见图片格式(PNG/JPEG/GIF/SVG/WebP)SHALL 以图片形式预览;其他二进制文件 SHALL 展示"暂不支持预览"的提示及文件基本信息(文件名、大小),MUST NOT 将二进制内容当作文本渲染导致乱码或卡死。

#### Scenario: 图片预览

- **WHEN** 用户点击一个 `.png` 文件
- **THEN** 预览区以图片形式展示,超出区域时自适应缩放

#### Scenario: 二进制文件提示

- **WHEN** 用户点击一个 `.exe` 或 `.zip` 文件
- **THEN** 预览区展示不支持预览的提示与文件名、大小信息

### Requirement: 大文件降级

超过阈值(默认 5 MB)的文本文件 SHALL 走降级渲染:仅加载文件开头部分(默认前 1 MB)并明确提示"文件过大,已截断展示";降级过程 MUST NOT 阻塞界面。被截断展示的文件 SHALL 同时明示其代码理解覆盖范围受限(符号未被索引,或仅覆盖已加载部分),MUST NOT 让用户以为大纲与跳转覆盖了整份文件。

#### Scenario: 超大日志文件

- **WHEN** 用户点击一个 50 MB 的 `.log` 文件
- **THEN** 预览区在短时间内展示文件开头内容与截断提示,界面全程可交互

#### Scenario: 截断文件的代码理解范围明示

- **WHEN** 用户点击一个 50 MB 的 `.c` 文件
- **THEN** 预览区在截断提示之外明示该文件的符号索引覆盖受限,大纲区给出对应说明

### Requirement: 按行定位与高亮

预览区 SHALL 支持按行定位:打开文件时若指定了目标行,SHALL 将该行滚动到可见区域(尽量居中)并施加短暂的行高亮标识,便于用户在跳转后立刻找到落点。该通道 SHALL 被所有导航入口共用(跳转到定义、查找引用、文件大纲、全局符号搜索、全文搜索结果、导航栈前进/后退)。

该要求 SHALL 以**不变量**方式成立,不按渲染通道切分:

> **凡指定了目标行,当前渲染通道 MUST 把该行对应的内容定位到可见区域并短暂标识。** 若该通道没有"行"的概念(如 Markdown 富文本渲染视图),SHALL 定位到**该源码行所对应的渲染元素**(如该行的标题、段落),MUST NOT 因为"渲染视图没有行"而静默不动作。

在**当前已打开文件内**定位到某行时,SHALL 直接滚动定位,不要求重新读取文件内容;跨文件跳转仍按既有约定从磁盘重新读取目标文件。目标行号超出文件实际行数,或文件因大文件降级被截断而目标行落在截断范围之外时,SHALL 定位到可定位的最近位置并给出明确提示,MUST NOT 报错、白屏或使预览区失去内容。

#### Scenario: 跨文件跳转定位到指定行

- **WHEN** 用户从符号搜索结果中选择 `handler.go:42`
- **THEN** 预览区打开 `handler.go`,第 42 行滚动到可见区域并短暂高亮

#### Scenario: 当前文件内定位不重读文件

- **WHEN** 用户在当前文件的大纲中点击某个函数
- **THEN** 预览区滚动到该函数定义行并短暂高亮,不重新读取该文件、不出现内容闪烁

#### Scenario: Markdown 富文本视图中的行定位

- **WHEN** 用户在 Markdown 富文本(渲染)视图下,从大纲中点击某个标题
- **THEN** 渲染视图滚动到该标题对应的渲染元素并短暂标识,**停留在富文本视图**,MUST NOT 静默无反应,也 MUST NOT 为了定位而强制切换到源码视图

#### Scenario: 目标行超出可定位范围

- **WHEN** 目标行号大于文件实际行数,或该行落在被截断文件的未加载部分
- **THEN** 预览区定位到最近的可定位位置并提示目标行不可定位,文件内容照常展示

### Requirement: 只读预览区的光标键盘导航

代码预览区 SHALL 支持**用键盘移动光标与扩展选区**(逐字符 / 逐行 / 翻页 / 行首行尾等),使用户能在不使用鼠标的情况下在文件内定位。

**该能力 MUST NOT 以放开编辑为代价**:预览区仍 SHALL 拒绝一切对文档内容的修改。**只读 MUST 由"拒绝修改"来保证,而不是由"关闭光标"来保证** —— 后者会连同键盘可达性一并关掉。

只读保证 SHALL 覆盖**所有可能的写入路径**,至少包括:键盘输入、粘贴、拖放、输入法组合、以及浏览器原生菜单中的编辑动作。

#### Scenario: 键盘在文件内移动光标

- **WHEN** 用户把焦点移到预览区,使用方向键、翻页键、行首/行尾键
- **THEN** 光标在代码中相应移动,当前位置可见

#### Scenario: 光标可用不等于可编辑

- **WHEN** 用户在预览区尝试键盘输入、粘贴、拖入文本或使用输入法
- **THEN** 文档内容不发生任何变化

### Requirement: 键盘焦点在预览区时的可见性

预览区持有焦点时 SHALL 有可见标识,且光标位置 SHALL 可见 —— 与目录树、大纲的焦点标识口径一致,使用户在三个面板间移动时始终知道"现在在哪、光标在哪"。

#### Scenario: 焦点落在预览区

- **WHEN** 用户用键盘把焦点移入预览区
- **THEN** 预览区呈现焦点标识,且光标位置可辨认

### Requirement: 导航到达之后必须可就地继续

凡"导航到某个代码位置"的动作(跳转到定义、选中一条引用、搜索结果跳转、大纲定位、导航历史前进/后退),**到达之后,用户 SHALL 能在目标处直接继续下一个动作,不需要额外的鼠标操作或重新定位。**

这条要求 SHALL 覆盖到达后的**全部相关状态**,而不只是其中一项:

- **视图**:目标行在可见区域内;
- **标识**:目标位置有可见提示;
- **焦点**:落在用户下一步会操作的控件上(具体归属由各入口的动线决定);
- **文本光标(caret)**:落在**目标位置**,使 `↓` 从目标行开始移动、对光标处符号生效的操作(如查找引用)作用于**目标符号**。

**只满足其中一部分不构成满足本要求。** 已发生的四次缺陷都是"入口成立、到达之后不可继续":面板能开不好退、能 Tab 到预览区却进不了编辑器、面板能弹出却选不中、跳转能到达而 caret 没跟过去。**逐条补要求会补出第五次 —— 本要求的层次就是为覆盖尚未出现的那一次而定的。**

**焦点与 caret 是两个独立资源,MUST NOT 相互替代**:焦点回答"按键作用在哪个控件",caret 回答"编辑器里光标在哪"。某些入口(如引用/全文结果面板)**焦点有意留在结果列表**以便用户继续挑选,**而 caret 同时落在目标处** —— 两者同时成立,不是取舍。

#### Scenario: 跳转后可直接用键盘继续

- **WHEN** 用户用键盘跳转到某个符号的定义处
- **THEN** 目标行可见且有标识,**caret 位于目标行**;按 `↓` 从目标行开始移动;对光标处符号触发查找引用,作用于**该符号**而非文件开头的内容

#### Scenario: 焦点留在结果列表时 caret 仍落在目标

- **WHEN** 用户在引用结果面板中选中一条并激活,该面板按设计保持打开、焦点留在列表
- **THEN** 焦点仍在结果列表(可继续上下挑选),**同时编辑器内的 caret 已位于该条引用所在位置** —— 用户 Tab 进编辑器即处于正确位置
