# local-file-takeover Specification

## Purpose

让用户在浏览器中直接打开本地文件时，根据自己选择的文件后缀自动进入 Lectern 阅读，并能够清楚了解授权状态、控制接管范围、在读取失败时恢复操作，减少重复选择文件的步骤。

## Requirements

### Requirement: 本地文件自动打开

扩展 SHALL 在功能启用、文件网址访问已授权且后缀匹配时，将浏览器顶层本地文件导航接管至同一标签页的单文件查看器。MUST 仅接受本机 `file://` 地址，不接管 HTTP(S)、目录、子框架或网页子资源。文件名匹配 SHALL 不区分大小写，正确处理 URL 编码、空格、中文、查询和片段。不具备可预览能力的二进制格式 MUST NOT 纳入候选。

#### Scenario: 打开匹配文件
- **WHEN** 用户打开已勾选后缀的本地 Markdown、SQL 或 Java 文件
- **THEN** 当前标签页直接展示对应预览，支持原有单文件大纲和适用的文件内导航

#### Scenario: 无关导航不受影响
- **WHEN** 用户打开未勾选后缀、HTTP(S) 地址、目录或加载子资源
- **THEN** 浏览器维持原有行为，不新增 Lectern 标签页；无末尾斜杠且目录名带匹配后缀时，在识别目录响应后恢复浏览器目录页

#### Scenario: 文件刷新
- **WHEN** 外部修改本地文件后用户刷新自动打开的查看器
- **THEN** 查看器重新读取文件，展示最新内容，不重新弹出文件选择器

### Requirement: 接管范围配置

用户 SHALL 从查看器的设置入口配置总开关、后缀多选、全选、清空与恢复默认。配置 SHALL 持久保存并应用于之后的导航。初始总开关 SHALL 开启，默认选择代码、Markdown 与纯文本后缀，HTML 和图片默认不选。候选 SHALL 与实际预览支持格式同源，后缀规则不额外解释为整文件名规则。保存失败 MUST 可见且不得显示成功。

#### Scenario: 配置持久生效
- **WHEN** 用户取消 SQL、保存设置并重新打开查看器
- **THEN** SQL 保持未选中，后续 SQL 导航不再被接管

#### Scenario: 停用与清空
- **WHEN** 用户关闭总开关或清空全部后缀并保存
- **THEN** 之后不接管任何文件，已打开的文件仍可阅读

### Requirement: 授权与失败恢复

设置 SHALL 展示文件网址授权状态，并提供 Chrome 扩展详情入口和手动开启说明。权限未授予或撤销时 MUST 明示原因，原生文件选择入口仍可用。自动打开失败时 SHALL 展示错误和重试、手动选择入口。URL 自动读取 SHALL 有 64 MiB 上限，超过时给出手动选择路径；成功读取的文本仍遵循现有大于 5 MiB 仅预览前 1 MiB 的规则。

#### Scenario: 首次授权
- **WHEN** 用户尚未开启允许访问文件网址
- **THEN** 设置显示未授权及开启方法，用户可继续通过文件选择器阅读

#### Scenario: 无法读取
- **WHEN** 文件不存在、权限被撤销或文件超过自动读取上限
- **THEN** 展示明确错误及恢复入口，不停留在永久加载状态
