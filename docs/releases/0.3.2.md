# Lectern 0.3.2

A full visual restyle plus keyboard access work on the help panel. No change to
what the extension is allowed to do: still zero network, still read-only, still
no permissions.

## Changed

- New reading-oriented theme in both light and dark. Warm paper background,
  warm dark counterpart, and a syntax palette rebuilt around six roles rather
  than a colour per token type.
- Scrollbars are themed. The browser's default scrollbar is a neutral grey; on
  a warm background it read as a cold strip down the middle of the window.
  `color-scheme` is now bound to the selected theme rather than to the
  operating system's preference, so switching the theme inside the extension
  also switches the scrollbars and form controls.

## Fixed

- The keyboard help panel now manages focus: opening it moves focus into the
  panel, `Tab` cycles inside it, and `Escape` closes it and returns focus to the
  control that opened it.
- The panel no longer claims an accessibility contract it does not implement.
  Declaring `aria-modal` without constraining focus is worse than not declaring
  it — assistive technology changes behaviour on that declaration, and the user
  has no way to find out why the experience does not match.

## Contrast

Text meets WCAG AA against its background throughout the interface, verified
against the shipped tokens and against pixels sampled from the released
screenshots.

One deliberate exception: line numbers in the editor gutter sit below AA. They
are supplementary information rather than text to be read, and raising them
makes them compete with the code for attention. The reasoning is recorded next
to the token in `src/styles.css` so it is not rediscovered and silently
"fixed".

## Artifacts

- `lectern-0.3.2.zip`: unzip and load the enclosed `lectern/` directory from
  `chrome://extensions`.
- `lectern-0.3.2-web-store.zip`: the exact root-manifest package submitted to
  the Chrome Web Store.
- Each archive has a corresponding `.sha256` file.

Both archives are plain outputs of the same clean build. They are not
obfuscated. Before publication the build passed the zero-network, read-only,
permission, language-coverage and TypeScript gates.

To verify from source instead of trusting an archive:

```bash
npm ci
npm run build
npm run check
```

Known non-blocking investigations remain documented in OpenSpec: an
intermittent Dockerfile highlighting assertion and an intermittent default-row
focus assertion under full-suite load.
