# 人工核验台账

**为什么单独一份**:有些性质**自动化验不到位** —— 浏览器/操作系统级的快捷键抢占、真实磁盘 I/O、观感与手感。这类项此前散落在各个 change 的任务里,**而 change 一归档,它们就冻在了没人会再打开的文件里**:已核验的没人知道验过、未核验的也没人知道欠着。

本台账把它们集中在一处并**长期维护**,规则三条:

1. **每一项只能是三种状态之一**:`已核验`(必须带**验证人 / 平台 / 日期**)、`未验证`(必须带**原因**)、`待核验`(必须带**谁来验**)。**没有第四种** —— "大概没问题"不是状态。
2. **已核验与未验证必须并列摆着。** 只列已核验,读的人看不出还有没验的;只列未验证,看不出验过的那半。**两者并列才说明问题。**
3. **写在消息里的验证要求不算数。** 一条只存在于对话里的"我去真机验",不会出现在任何完成度里 —— **要么落进这张表,要么落进某个 change 的任务,否则它迟早漂成一句谁也不负责的话。**

## 快捷键(浏览器/系统级抢占,自动化验不到)

> **为什么自动化不行**:CDP / puppeteer 派发的是**合成事件,只进渲染进程**,不触及浏览器 UI 与操作系统。合成 `blur` ≠ 真的 `⌘Tab`;合成 `keydown` 不会被书签管理器抢走。**用它得出的"没被抢占"是无效证据。**

## 已知偶发(原因未明,但产品行为已核验)

| 项 | 状态 | 依据 |
|---|---|---|
| 目录树「容器获得焦点时活动行默认落在首行」偶发失效 | **已知偶发 · 未修** | **产品行为经真人与 300+ 条断言核验正常**,失效时按一次方向键即恢复。现象:目录树**确实持有焦点**、行已渲染,但 `aria-activedescendant` 始终为空。**已证伪的假说**:"onFocus 拿到旧闭包的空 rows 且补设 effect 不再重跑" —— 据此加了焦点触发的重试,**仍偶发**。定点复现脚本(40 轮真实重挂)**未能复现**,说明需要全套件的负载条件。E2E 里走 `checkKnownFlaky` 通道:**照常执行、失败照常打印、单独计数,但不把套件染红** —— 因为它红时最可能被误判成"我刚改的东西坏了"。追踪于 `chase-tree-focus-race` |
| `scripts/shot-readme.mjs` 载入项目后偶发 `Attempted to use detached Frame` | **已知偶发 · 未查** | 三次运行中出现一次:同一份构建、同一段代码,页面在项目载入后被关闭,其余两次全程正常。**只发生在截图/走查脚本里,不在产品中** —— 产品侧同一操作序列由 E2E 与真人走查覆盖。**未查根因**:冻结期不开新战场,且它不阻断发货(重跑即可)。记在这里而不是让它留在某次输出里,是因为**下一个人看到它时应该知道'这是已知的',而不是以为自己刚弄坏了什么** |

## 维护约定

- **新增一条"只有真人能验"的性质时,立刻登记在此**,不要只写在消息里或某个会归档的任务里。
- **状态变更要改这里**,并保留原状态的日期 —— 台账的价值在于**能看出某条欠了多久**。
- 对外文档若引用"我们验证了什么",**应指向本表而不是复述**;复述会漂移,而漂移时两边都还是绿的。
