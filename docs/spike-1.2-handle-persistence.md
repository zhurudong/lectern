# Spike 1.2:目录句柄持久授权验证记录

## 验证目标

扩展页内 `showDirectoryPicker()` → 句柄存 IndexedDB → 重启浏览器后 `queryPermission`/`requestPermission` 重连,确认授权弹窗频率是否可接受(design.md D1 的核心风险)。

## 代码路径(已实现)

- 句柄持久化:`src/lib/recent.ts`(IndexedDB `code-viewer/recent-projects`,句柄结构化克隆存储)
- 重连流程:`src/lib/access.ts` `reconnectRecent()`——先 `queryPermission({mode:'read'})`,非 granted 时在用户手势(点击最近项目)内 `requestPermission()`,granted 后用 `keys().next()` 探测目录仍可读,句柄失效返回 `gone` 走降级 UI。

## 预期行为(基于 Chrome 122+ 文档)

- Chrome 122 起 File System Access 支持持久授权:重新授权弹窗中提供"每次访问时允许"选项;用户选择后,后续会话 `queryPermission()` 直接返回 `granted`,零弹窗重连。
- 用户若只选"允许一次",则每个浏览器会话首次重连时弹一次授权——design.md 已评估为可接受的最差情况。

## 实测结论

**2026-08-16 收口(spike 通过):** 用户完成真机使用(含重启浏览器后经最近项目重连,及走查清单的 5+2 步)后反馈"目前暂时用起来还可以",未报告授权弹窗异常或其他阻碍。规格阶段(方案负责方)据此判定:授权弹窗频率可接受,授权体验成立,**D1(FSA 入口架构)成立**。

下方三个观察复选项用户未逐项记录,保持未勾——"整体体验可接受"已覆盖决策所需,不补记未观察到的细节。
