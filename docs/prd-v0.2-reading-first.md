## 1. 市场结论

### 1.1 竞品格局

| 竞品 | 覆盖场景 | 结构性短板(我们的机会) |
|---|---|---|
| **vscode.dev / github.dev** | 同样用 File System Access 打开本地目录,编辑器能力远强 | ① 是云端 Web App,打开即联网,受限网络/合规环境不可用;② **本地文件夹场景下没有语言服务**,IntelliSense / 跳转定义在虚拟化环境中受限,跨文件导航基本失效;③ 编辑器心智,不为"读"设计 |
| **原生 IDE(VS Code / JetBrains)** | 能力最全 | 需要安装、需要索引配置;临时机器 / 受管终端 / 借用电脑上装不了;为写代码优化,读代码是副产品 |
| **Sourcegraph / OpenGrok / SciTools Understand** | 代码理解能力强 | 需要服务端部署或桌面重装,面向团队采购,个人与临时场景成本过高 |
| **GitHub 网页版 / Octotree 类扩展** | 阅读体验好 | 只能读**已推送到远端**的代码,读不了本地目录、未提交产物、下载的压缩包、AI 生成的工作区 |

**空位**:一个**零网络、免安装重负担、专为"读"优化**、且**具备跨文件代码理解能力**的本地代码阅读器。这个格子目前没有像样的占位者。

### 1.2 需求侧趋势(为什么是现在)

2026 年开发者角色正从"作者"转向"审计者":生成变快,**验证成为瓶颈**。行业调研显示"审查与验证 AI 生成代码的质量与安全"被列为 AI 时代第一重要技能(47%),75% 的开发者仍会逐段人工审阅 AI 生成代码,45.2% 的人认为调试 AI 代码比自己写更费时。

**推论**:读代码的时长在涨,但市面工具仍全部围绕"写"来设计。"读"这个动作缺少一等公民工具。

### 1.3 产品定位(一句话)

> **Lectern 是一个零网络的本地代码阅读器 —— 不装 IDE、不上传代码,打开就能读懂一个陌生代码库。**

不是"浏览器里的 VS Code",而是**阅读器**。对标物是 Kindle 之于 Word,不是 Word 的精简版。

## 2. 差异化能力清单(按优先级)

### P0 —— 离线代码理解层(Code Intelligence,无语言服务器)

**这是与 vscode.dev 拉开差距的核心。** 竞品在本地目录场景恰恰缺这一块。

必须让用户可感知地做到:

1. **全项目符号索引**:在 Web Worker 后台构建,不阻塞首屏;10,000 文件规模下可用。
2. **跳转到定义**:`Cmd/Ctrl` + 点击标识符 → 跳到同项目内的定义处,跨文件;`Alt+←` 返回上一处,形成可回溯的导航栈。
   > 2026-08-17 修订:初稿写的 F12 是产品阶段的错误——F12 是 Chrome DevTools 保留键,页面大概率拦不住。主入口必须落在非浏览器保留键上;同理 `Ctrl+Shift+O` 在 Windows/Linux 是 Chrome 书签管理器,Win/Linux 需实测并备好备用键位。**浏览器级快捷键冲突不可由 E2E 覆盖**(CDP 合成事件不触发浏览器 UI 快捷键),必须真机人工验证。
3. **查找引用**:侧栏列出某符号在项目内被引用的位置,点击直达。
4. **文件大纲(Outline)**:当前文件的类/函数/方法结构,点击定位;大文件读代码的必需品。
5. **全局符号搜索**:按符号名跨项目跳转(现有 `⌘K` 只搜文件名)。键位:Mac `⌘⇧O`;Win/Linux 与 Chrome 书签管理器冲突,需实测后定夺备用键位。
6. **全文内容搜索**:`⌘⇧F` / `Ctrl+Shift+F`,跨文件搜正文,结果流式回填、可点击直达行。

> 实现提示(不作强制,规格阶段自行裁决):项目已打包 CodeMirror 6 / Lezer 的 15 种语言解析器,复用 Lezer 语法树在 Worker 里抽取符号,可能比引入 tree-sitter WASM 更省包体积。请在 design.md 里对比论证。允许"定义跳转"是启发式的(同名符号多候选时给候选列表),**不承诺编译级精确**——这一点必须在 spec 的验收标准里写清,不许含糊。

### P1 —— 阅读者工作流(Reading Workflow)

**IDE 完全没有的一层,是"阅读器"身份的立身之本。**

1. **阅读进度**:文件级"已读/未读"标记,目录树上可视化;让"读完一个库"变成可完成的任务。
2. **书签与行内笔记**:在某文件某行留标记与文字,本地持久化(IndexedDB),侧栏聚合。
3. **阅读轨迹**:自动记录本次会话的文件访问与跳转链,可回看。
4. **导出导读**:把书签/笔记/轨迹导出成一份 Markdown"代码导读",可交给同事或贴进 PR/文档。这是天然的口碑传播点。

### P2 —— 隐私可验证与分发

1. **零网络自证**:manifest 不申请任何 host_permissions、CSP 禁外联,并在 UI 上给用户一个可点开的"隐私说明"(说明代码不出本机、扩展无网络权限)。这是面向合规敏感人群的转化钩子,也是竞品(云端 Web App)结构上给不了的承诺。
2. **Chrome Web Store 上架素材**:截图、说明文案围绕"零网络 + 读懂陌生代码库"两个卖点。

## 3. 非目标(明确不做)

- **不做编辑与保存**(继续只读;只读是定位,不是短板)。
- **不接任何 AI/LLM、不做任何网络请求**(零网络是核心资产,一旦破例整个定位失效)。
- **不做 Git 集成 / diff**(v0.3 再议)。
- **不做编译级精确的语义分析**(不引入 LSP、不跑 tsserver)。
- **不做多语言全覆盖**:P0 的代码理解层允许只覆盖现有 15 类语言中的一个子集,但**必须在 UI 上明示哪些语言支持跳转**,不能让用户猜。

---

## 4. 约束与验收底线

- 零网络:构建产物中不得出现远程资源引用;manifest 无 host_permissions。
- 性能:10,000 文件项目,索引构建不阻塞首屏交互;跳转定义 P95 < 200ms。
- 包体积:新增依赖需在 design.md 说明体积影响;如超过当前产物体积 50%,须给出取舍论证。
- 兼容:Chrome 122+,MV3。
- 现有能力(目录树、预览、Markdown、主题、⌘K、大文件降级)**不得回归**,E2E 必须仍全绿。
